# 4.1 検証項目（Test Plan）の書き方 (วิธีการเขียนหัวข้อการทดสอบ)

## 📖 ทฤษฎี (Theory - Engineering Perspective)
**検証項目 (Test Plan / Test Specification)** คือหัวใจสำคัญของกระบวนการวิศวกรรม (V-Model) การออกแบบบอร์ดจะถือว่าสมบูรณ์ไม่ได้ถ้ายังไม่ผ่านการทดสอบตามเป้าหมาย Test Plan ที่ดีต้องครอบคลุม 3 สภาวะ:
1. **Nominal Condition (สภาวะปกติ):** ทดสอบการทำงานทั่วไปตามสเปค
2. **Boundary Condition (สภาวะขอบเขต):** เช่น ทดสอบที่แรงดันไฟต่ำสุด/สูงสุด (Min/Max Vcc) หรือ อุณหภูมิสูงสุด (Max Temp)
3. **Abnormal Condition (สภาวะผิดปกติ):** เช่น การทดสอบโหลดช็อต (Short circuit), การถอดสายกลางคัน (Hot-plug), การใส่ไฟสลับขั้ว

## 💡 ทริคหน้างาน (OJT Tricks)
- **เขียน Test Plan ก่อนบอร์ดจะผลิตเสร็จ:** อย่ารอให้บอร์ดจริงมาถึงโต๊ะแล้วค่อยคิดว่าจะเทสต์อะไร! ให้ใช้เวลาระหว่างรอโรงงานผลิต PCB (Lead time) ในการเขียน Test Plan, ซื้อสายไฟ, สั่งทำ Test Jig และเตรียมสคริปต์อัตโนมัติให้พร้อม พอของมาถึงปุ๊บก็ลุยได้เลย
- **ผลการทดสอบต้องมี "เกณฑ์ผ่าน/ไม่ผ่าน" ที่ชัดเจน (Pass/Fail Criteria):** อย่าเขียนหัวข้อเทสต์แบบลอยๆ เช่น "ตรวจสอบแรงดันไฟ 3.3V" ให้เขียนระบุไปเลยว่า "แรงดันไฟ 3.3V ต้องอยู่ในช่วง 3.13V ถึง 3.46V (Tolerance $\pm5\%$)" เพื่อไม่ให้เกิดการเถียงกันทีหลัง

## 🗣️ คำศัพท์และประโยคภาษาญี่ปุ่น
- **検証項目 (Kenshō Kōmoku):** Test Plan / Test items (หัวข้อการทดสอบ)
- **評価 (Hyōka):** Evaluation (การประเมิน/การทดสอบประสิทธิภาพ)
- **合否判定 (Gōhi Hantei):** Pass/Fail Judgment (การตัดสินผ่าน/ไม่ผ่าน)
- **規格 (Kikaku):** Standard / Specification (มาตรฐาน/เกณฑ์)
- **ワーストケース (Wāsuto Kēsu):** Worst-case (กรณีเลวร้ายที่สุด)

**ประโยคที่ใช้บ่อย:**
> 「次期基板の検証項目リストを作成しました。ワーストケースの条件も網羅しています。」
> *(Jiki kiban no kenshō kōmoku risuto o sakusei shimashita. Wāsutokēsu no jōken mo mōra shite imasu.)*
> "ได้จัดทำรายการหัวข้อการทดสอบของบอร์ดรุ่นถัดไปเรียบร้อยแล้วครับ ซึ่งครอบคลุมเงื่อนไขการทดสอบแบบ Worst-case ไว้ด้วยครับ/ค่ะ"
