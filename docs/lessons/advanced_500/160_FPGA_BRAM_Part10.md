## 1. ทฤษฎีวิศวกรรมเชิงลึก (高度なエンジニアリング理論)

### 1.1 แบบจำลองความผิดพลาดทางกายภาพของเซลล์หน่วยความจำ SRAM (SRAM Physical Defect & Fault Modeling)
ในกระบวนการผลิตเวเฟอร์ซิลิคอนระดับนาโนเมตร (Semiconductor Fabrication) ข้อบกพร่องทางกายภาพ เช่น อนุภาคฝุ่นตกค้าง (Particle Contamination), รอยรั่วของชั้นออกไซด์ (Gate Oxide Pinhole), หรือความต้านทานสัมผัสสูงผิดปกติที่รูคอนแทกต์ (High-Resistance Contact Vias) นำไปสู่ความผิดพลาดทางวงจรไฟฟ้าในเซลล์ 6T SRAM ของ BRAM และ UltraRAM:

```
               แบบจำลองความผิดพลาดทางกายภาพของ 6T SRAM CELL
               
                         VDD
                          │
                   ┌──────┴──────┐
             P1  ──┤             ├──  P2
            (Pull-up)│           │(Pull-up)
                   ├──────┬──────┤
             N1  ──┤      │      ├──  N2 (Pull-down)
                   │      │      │
     Bitline ──[ N3 ]── Q │ /Q ──[ N4 ]── ~Bitline (Pass-Gates)
     (BL)       (Pass)    │       (Pass)     (~BL)
                          ▼
                         GND
```

#### การจำแนกโมเดลความผิดพลาดตามมาตรฐาน IEEE 1500 / IEEE 1149.1:
1. **Stuck-At Fault (SAF):**  
   ขั้วโหนดเก็บประจุ $Q$ หรือ $/Q$ ช็อตลงกราวด์ ($SA0$) หรือช็อตเข้าไฟเลี้ยง $V_{dd}$ ($SA1$) ทำให้เซลล์มีค่าคงที่ตายตัวตลอดเวลา
2. **Transition Fault (TF):**  
   เซลล์ไม่สามารถเปลี่ยนสถานะได้สำเร็จ ($0 \to 1$ ล้มเหลว หรือ $1 \to 0$ ล้มเหลว) มักเกิดจากทรานซิสเตอร์ Pull-up (P1/P2) มีค่าความนำไฟฟ้าต่ำเกินไป
3. **Address Decoder Fault (AF):**  
   ความบกพร่องในวงจรถอดรหัสแอดเดรส ส่งผลให้:
   * ไม่มีเซลล์ใดถูกเลือกเลยเมื่อส่งแอดเดรส $A$
   * เซลล์ $A$ ถูกเลือกพร้อมกับเซลล์ $B$ (แอดเดรสหลายตัวชนกัน)
   * แอดเดรส $A$ กลับไปเปิดเซลล์ $B$ แทน
4. **Coupling Fault (CF - ความผิดพลาดจากการเหนี่ยวนำข้ามเซลล์):**  
   การสลับสถานะของเซลล์ข้างเคียง (**Aggressor Cell: $C_a$**) ส่งผลรบกวนเซลล์ตกเป็นเหยื่อ (**Victim Cell: $C_v$**):
   * **Inversion Coupling (CFin):** การเปลี่ยนสถานะของ $C_a$ ทำให้ค่าใน $C_v$ กลับทิศ ($0 \leftrightarrow 1$)
   * **Idempotent Coupling (CFid):** การเปลี่ยนสถานะของ $C_a$ บังคับให้ $C_v$ ถูกล็อกเป็นค่าคงที่ (เช่น บังคับเป็น 0 เสมอ)
   * **State Coupling (CFst):** เซลล์ $C_v$ ถูกบังคับค่าเมื่อ $C_a$ อยู่ในสถานะใดสถานะหนึ่งโดยเฉพาะ
5. **Data Retention Fault (RF):**  
   เซลล์สูญเสียประจุเมื่อถูกปล่อยทิ้งไว้เป็นระยะเวลาหนึ่ง (Hold Time) โดยไม่มีการอ่านหรือเขียน

### 1.2 ทฤษฎีและขั้นตอนวิธี March C- Algorithm (The 10N March Test Standard)

การทดสอบหน่วยความจำแบบดั้งเดิม เช่น การเขียน 0 ทั้งหมดแล้วอ่าน หรือการเขียนตารางหมากรุก (Checkerboard Pattern: `0101...`) **ไม่สามารถตรวจจับ Address Decoder Faults และ Dynamic Coupling Faults ได้!**

มาตรฐานสากลสำหรับการทดสอบหน่วยความจำ SRAM ฝังตัว (Embedded SRAM BIST) คือ **March C- Algorithm** ซึ่งมีความซับซ้อนเชิงเวลา $10N$ (โดย $N$ คือจำนวนแอดเดรสทั้งหมด):

$$\text{March C-} = \{ \Uparrow (w0); \Uparrow (r0, w1); \Uparrow (r1, w0); \Downarrow (r0, w1); \Downarrow (r1, w0); \Updownarrow (r0) \}$$

```
                โครงสร้าง 6 สเตปของ MARCH C- ALGORITHM (10N)
                
   สเตป  ทิศทางการนับแอดเดรส   การดำเนินการ (Operations)      จำนวนโอเปอเรชัน
   ----  ------------------   -------------------------      ---------------
   M0    ขึ้น (Up: 0 -> N-1)  เขียน 0 (w0)                    1N
   M1    ขึ้น (Up: 0 -> N-1)  อ่าน 0 ตรวจสอบ, เขียน 1 (r0, w1)  2N
   M2    ขึ้น (Up: 0 -> N-1)  อ่าน 1 ตรวจสอบ, เขียน 0 (r1, w0)  2N
   M3    ลง (Down: N-1 -> 0)  อ่าน 0 ตรวจสอบ, เขียน 1 (r0, w1)  2N
   M4    ลง (Down: N-1 -> 0)  อ่าน 1 ตรวจสอบ, เขียน 0 (r1, w0)  2N
   M5    ใดๆ (0 -> N-1)       อ่าน 0 ตรวจสอบขั้นสุดท้าย (r0)    1N
   -------------------------------------------------------------------------
   ผลรวมโอเปอเรชันทั้งหมด (Total Memory Access Operations) =  10N
```

#### การพิสูจน์ความครอบคลุมของ March C- (Fault Coverage Proof):
* **ตรวจจับ SAF $100\%$:** ขั้นตอน $M_1$ และ $M_2$ มีการอ่านทั้ง 0 และ 1 ในทุกๆ เซลล์
* **ตรวจจับ TF $100\%$:** ขั้นตอน $M_1$ ทดสอบการเปลี่ยน $0 \to 1$ และ $M_2$ ทดสอบการเปลี่ยน $1 \to 0$
* **ตรวจจับ AF $100\%$:** การอ่านและเขียนกลับสลับทิศทางทั้งแบบนับขึ้น ($\Uparrow$) และนับลง ($\Downarrow$) ทำให้หากมีสองแอดเดรสชี้ไปยังเซลล์เดียวกัน ค่าที่เพิ่งเขียนทับจะถูกเปิดโปงในการอ่านแอดเดรสถัดไปทันที
* **ตรวจจับ CFid และ CFin $100\%$:** การสแกนสองทิศทางครอบคลุมทั้งกรณีที่ Aggressor มีแอดเดรสน้อยกว่า Victim ($a < v$) และ Aggressor มีแอดเดรสมากกว่า Victim ($a > v$)

### 1.3 สถาปัตยกรรมฮาร์ดแวร์ BIST Controller สำหรับ Power-On Self-Test (POST BIST Engine)

ในระบบที่มีความปลอดภัยขั้นวิกฤต วงจร BIST Controller จะถูกฝังรวมอยู่ใน RTL ของ FPGA เพื่อรันการทดสอบ **Power-On Self-Test (POST)** อัตโนมัติทันทีที่ชิปโหลดบิตสตรีมเสร็จ ก่อนที่จะส่งสัญญาณอนุญาตให้วงจรประมวลผลหลักเริ่มทำงาน:

```
                    สถาปัตยกรรม HARDWARE BIST CONTROLLER
                    
            ┌───────────────────────────────────────────────┐
            │           BIST FSM Master Controller          │
            │           (State: M0 -> M1 -> ... -> M5)      │
            └───────┬──────────────┬──────────────┬─────────┘
                    │              │              │
                    ▼              ▼              ▼
            ┌──────────────┐┌──────────────┐┌──────────────┐
            │Up/Down Counter││Pattern Gen   ││Read Compare  │
            │Address (ADDR)││Data In (DIN) ││Logic (Error) │
            └───────┬──────┘└──────┬───────┘└──────▲───────┘
                    │              │               │
                    ▼              ▼               │ DOUT
            ═══════════════════════════════════════╧═════════
                       BLOCK RAM / UltraRAM MACRO
            ═════════════════════════════════════════════════
                                                   │
                                                   ▼
                                         [ BIST_DONE / BIST_PASS ]
                                         (หากล้มเหลว: กักขังระบบใน RESET!)
```

```verilog
// นิยาม State Machine ของ March C- Controller
typedef enum logic [2:0] {
    ST_IDLE,
    ST_M0_W0,       // Up: write 0
    ST_M1_R0_W1,    // Up: read 0, write 1
    ST_M2_R1_W0,    // Up: read 1, write 0
    ST_M3_R0_W1,    // Down: read 0, write 1
    ST_M4_R1_W0,    // Down: read 1, write 0
    ST_M5_R0,       // Any: read 0
    ST_DONE
} bist_state_t;
```

### 1.4 การทดสอบความเร่งทางอุณหภูมิและการเบิร์นอิน (Burn-In Qualification & Arrhenius Physics)

เพื่อคัดกรองชิปที่มีความบกพร่องในระยะเริ่มต้น (Infant Mortality) ออกก่อนส่งมอบให้ลูกค้า ชิป FPGA หรือบอร์ดวงจรจะต้องผ่านการทดสอบ **Burn-In Test** ภายใต้อุณหภูมิและแรงดันไฟฟ้าสูง

#### แบบจำลองของอาร์เรเนียส (Arrhenius Life Acceleration Model):
อัตราเร่งความเสียหายจากอุณหภูมิคำนวณได้จาก:

$$AF_T = \exp \left[ \frac{E_a}{k_B} \left( \frac{1}{T_{use}} - \frac{1}{T_{stress}} \right) \right]$$

โดยที่:
* $E_a$: พลังงานกระตุ้นความล้มเหลวของสารกึ่งตัวนำซิลิคอน (Activation Energy โดยทั่วไปสำหรับ SRAM Oxide Defect $E_a \approx 0.7\text{ eV}$)
* $k_B$: ค่าคงที่ของโบลต์ซมันน์ ($8.617 \times 10^{-5}\text{ eV/K}$)
* $T_{use}$: อุณหภูมิการใช้งานจริงในหน่วยเคลวิน ($K = ^\circ\text{C} + 273.15$)
* $T_{stress}$: อุณหภูมิในการทดสอบ Burn-In ในตู้ควบคุม ($K$)

#### แบบจำลองความเร่งจากแรงดันไฟฟ้าเกิน (Voltage Acceleration Factor: $AF_V$):
$$AF_V = \exp \left[ \beta \cdot (V_{stress} - V_{use}) \right]$$
โดย $\beta$ เป็นค่าคงที่ของออกไซด์ (ประมาณ $1.5 - 3.0\text{ V}^{-1}$)

#### ปัจจัยเร่งรวม (Total Acceleration Factor: $AF_{total}$):
$$AF_{total} = AF_T \times AF_V$$
อายุการใช้งานเทียบเท่าที่จำลองได้ ($t_{equivalent}$):
$$t_{equivalent} = t_{burn\_in} \times AF_{total}$$

## 2. ทริคหน้างาน OJT แบบ Step-by-Step (現場の実践テクニック)

### 2.1 กรณีศึกษาความล้มเหลวหน้างาน: กล่องควบคุม ADAS ยานยนต์สตาร์ทไม่ติดที่อุณหภูมิติดลบ -40°C (Automotive ADAS ECU Cold-Boot Failure in Hokkaido)

```
+----------------------------------------------------------------------------------------------------+
| กรณีศึกษาความล้มเหลวหน้างาน (現場の失敗事例)                                                                 |
| เหตุการณ์: กล่องควบคุมระบบช่วยขับขี่อัจฉริยะ (ADAS Tier-1 ECU) ติดตั้งในรถยนต์ทดสอบ ณ ลานทดสอบฮอกไกโดช่วงฤดูหนาว  |
| อาการ: รถยนต์ที่จอดข้ามคืน ณ อุณหภูมิ -40°C ไม่สามารถสตาร์ทระบบได้ โดย ECU ติดค้างในสถานะ Boot Failure         |
|        แต่เมื่อนำบอร์ดกลับมาทดสอบในห้องแล็บที่โตเกียวที่อุณหภูมิห้อง (25°C) บอร์ดกลับทำงานได้ปกติ 100% ไร้ปัญหา!    |
+----------------------------------------------------------------------------------------------------+
```

#### การวิเคราะห์หาสาเหตุรากเหง้าด้วยหลักการ 5 Whys (5 Whys Root Cause Analysis):

1. **ทำไมกล่อง ADAS จึง Boot Failure ที่อุณหภูมิ -40°C?**  
   *คำตอบ:* ซอฟต์แวร์ Bootloader ฟ้องว่าหน่วยความจำ BRAM ตรวจพบข้อมูลพิกัดเซนเซอร์บิดเบือน และระบบล็อกตัวเองเข้า Safe State

2. **ทำไม BRAM จึงอ่านข้อมูลผิดพลาดที่อุณหภูมิติดลบ แต่ทำงานได้ปกติที่ 25°C?**  
   *คำตอบ:* มีเซลล์ SRAM เซลล์หนึ่งมีข้อบกพร่องชนิดความต้านทานสัมผัสสูงที่รอยต่อ (Marginal Contact Defect) ทำให้แรงดันกระตุ้น $V_{th}$ ของทรานซิสเตอร์เกิดความไม่สมดุล เมื่ออุณหภูมิลดต่ำลงเป็น -40°C สภาพความคล่องตัวของพาหะ (Carrier Mobility) เปลี่ยนไปจนทำให้เซลล์ไม่สามารถรักษาสถานะลอจิก 1 ไว้ได้ (Cold-Temperature Retention Failure)

3. **ทำไมชิป FPGA ตัวที่มีเซลล์บกพร่องนี้จึงหลุดรอดจากกระบวนการผลิตมาได้?**  
   *คำตอบ:* ในสายการผลิตของโรงงาน มีการรันโปรแกรมตรวจสอบ BRAM โดยใช้เพียงแค่การเขียน `0x00000000` ทั้งหมด และ `0xFFFFFFFF` ทั้งหมด (Checkerboard แบบหยาบ) แล้วอ่านกลับ ซึ่งใช้เวลาเพียง 0.2 วินาที

4. **ทำไมการเขียน 0 ทั้งหมดและ 1 ทั้งหมดจึงตรวจไม่พบข้อบกพร่องนี้?**  
   *คำตอบ:* ข้อบกพร่องนี้เป็นชนิด **Idempotent Coupling Fault (CFid)** ร่วมกับ **Retention Weakness** ซึ่งจะแสดงอาการก็ต่อเมื่อเซลล์รอบข้างมีการเปลี่ยนสถานะ $0 \to 1$ ในขณะที่เซลล์เป้าหมายต้องถูกทิ้งค้างไว้ การเขียนแพทเทิร์นคงที่พร้อมกันทุกเซลล์ไม่สามารถกระตุ้น (Sensitize) ให้เกิดความผิดพลาดนี้ได้!

5. **ทำไมสายการผลิตจึงไม่รันขั้นตอนวิธี March C- ครบทั้ง 10N?**  
   *คำตอบ:* ฝ่ายผลิตต้องการลดเวลาการทดสอบต่อบอร์ด (Test Time per Unit) จาก 3 วินาทีเหลือ 0.5 วินาทีเพื่อเร่งยอดส่งมอบ จึงแอบปิดสเต็ป BIST March C- ในเฟิร์มแวร์ทดสอบโรงงาน โดยไม่ผ่านความเห็นชอบของฝ่ายประกันคุณภาพ (QA)!

### 2.3 คู่มือปฏิบัติงาน SOP: การทดสอบ BIST และการอนุมัติปล่อยผลิต (Zero-Defect BIST & Sign-Off SOP)

#### สเต็ปที่ 1: การฝังฮาร์ดแวร์ BIST March C- Controller ลงใน Bitstream
* กำหนดให้โมดูล BIST March C- เป็น **ด่านแรกสุดของระบบ (First Stage Boot)**
* เมื่อสัญญาณ `PROG_DONE` ของ FPGA ขึ้นสูง ให้ BIST Engine ควบคุม Address และ Data Bus ของ BRAM ทันที โดยปิดกั้นไม่ให้ Logic อื่นเข้าถึง (Bus Isolation):

```verilog
// วงจรสลับการเข้าถึง BRAM ระหว่าง BIST Engine กับ Application Logic
assign bram_addr = (bist_busy) ? bist_addr : app_addr;
assign bram_din  = (bist_busy) ? bist_din  : app_din;
assign bram_we   = (bist_busy) ? bist_we   : app_we;
```

#### สเต็ปที่ 2: การตรวจสอบเงื่อนไขความปลอดภัยและผลลัพธ์ Pass/Fail
* หาก BIST ทำงานครบ 6 สเตป ($10N$) โดยไม่พบข้อผิดพลาด ให้ขับสัญญาณ `BIST_PASS = 1` และปลดล็อกรีเซ็ตของระบบหลัก (`sys_rst_n <= 1'b1`)
* หากพบข้อผิดพลาดแม้แต่บิตเดียว:
  * บันทึกค่าแอดเดรสที่พัง (`FAIL_ADDR`) และบิตมาสก์ (`FAIL_BIT`) ลงใน Status Register
  * ขับสัญญาณเตือนฮาร์ดแวร์ และกักขังระบบหลักไว้ในสถานะ Reset ถาวร เพื่อป้องกันไม่ให้ทำงานในสภาวะที่ไม่ปลอดภัย

#### สเต็ปที่ 3: ข้อกำหนดการทดสอบอุณหภูมิ 3 สภาวะ (Three-Temperature Testing Sign-Off)
* สำหรับผลิตภัณฑ์เกรดยานยนต์ (AEC-Q100 Grade 1) และอากาศยาน (DO-254):
  * ต้องผ่านการรัน BIST March C- ครบทั้ง 3 สภาวะอุณหภูมิ:
    1. อุณหภูมิต่ำสุด (Cold Corner: $-40^\circ\text{C}$)
    2. อุณหภูมิห้อง (Nominal: $+25^\circ\text{C}$)
    3. อุณหภูมิสูงสุด (Hot Corner: $+125^\circ\text{C}$)

#### สเต็ปที่ 4: การลงนามอนุมัติการทดสอบสายการผลิต (Production Sign-Off Checklist)
* ห้ามตัดทอนขั้นตอน March C- ออกจากสายการผลิตจริงเด็ดขาด
* วิศวกรผู้ตรวจแบบ (Kenzu Reviewer) ต้องตรวจสอบบันทึกผลการทดสอบ ATE (Automated Test Equipment) ว่ามีตัวเลขครอบคลุม Fault Coverage $\ge 99.8\%$ ก่อนลงนามปล่อยล็อตการผลิต

## 4. ควิซวิเคราะห์ปัญหาระดับวิศวกรอาวุโส (上級技術クイズ)

### ข้อที่ 1: การคำนวณจำนวนรอบเวลาและระยะเวลาทดสอบ BIST March C- บนอาร์เรย์หน่วยความจำขนาดใหญ่

#### โจทย์คำถาม:
ในชิปประมวลผลเรดาร์อวกาศ มีการติดตั้งหน่วยความจำ On-Chip BRAM ขนาดรวม **$32,768\text{ Words}$** (ความกว้าง $64\text{ bits}$ ต่อเวิร์ด) ทำงานร่วมกับวงจรฮาร์ดแวร์ BIST Controller เพื่อรันการทดสอบตามขั้นตอนวิธี **March C- Algorithm (10N)**

กำหนดให้:
* สัญญาณนาฬิกาของการทดสอบ BIST: $f_{clk} = 200\text{ MHz}$ ($T_{clk} = 5.0\text{ ns}$)
* ในแต่ละสเต็ปของ March Element:
  * การดำเนินการแบบเขียนเดี่ยว ($w$): ใช้เวลา $1\text{ cycle/word}$
  * การดำเนินการแบบอ่านแล้วเขียน ($r, w$): หน่วยความจำ BRAM มี Read Latency เท่ากับ $1\text{ cycle}$ ทำให้รอบการอ่านและเขียนสลับกันใช้เวลาเฉลี่ย $2\text{ cycles/word}$
  * การดำเนินการแบบอ่านเดี่ยว ($r$): ใช้เวลา $1\text{ cycle/word}$
* มีวงจรหน่วงเวลาเปลี่ยนผ่าน State Machine ระหว่างแต่ละ March Element ($M_0 \to M_1 \to \dots \to M_5$) สเต็ปละ $8\text{ cycles}$ (รวม Overhead ทั้งสิ้น $6 \times 8 = 48\text{ cycles}$)

จงคำนวณหา:
1. จำนวนรอบสัญญาณนาฬิการวมทั้งหมด ($Total\_Cycles_{BIST}$) ที่ BIST Controller ต้องใช้ในการรันการทดสอบ March C- จนเสร็จสมบูรณ์
2. ระยะเวลาจริงในการทดสอบ ($T_{test\_time}$) ในหน่วยมิลลิวินาที (ms)
3. หากระบบมีข้อกำหนด Power-On Self-Test (POST) ว่าการทดสอบต้องเสร็จสิ้นภายใน $2.0\text{ ms}$ ระบบนี้สอบผ่านเกณฑ์เวลา POST หรือไม่?

* ก. $Total\_Cycles = 327,680\text{ cycles}$, $T_{test\_time} \approx 1.638\text{ ms}$, **ผ่านเกณฑ์ POST**
* ข. $Total\_Cycles = 327,728\text{ cycles}$, $T_{test\_time} \approx 1.639\text{ ms}$, **ผ่านเกณฑ์ POST**
* ค. $Total\_Cycles = 655,408\text{ cycles}$, $T_{test\_time} \approx 3.277\text{ ms}$, **ไม่ผ่านเกณฑ์ POST**
* ง. $Total\_Cycles = 163,840\text{ cycles}$, $T_{test\_time} \approx 0.819\text{ ms}$, **ผ่านเกณฑ์ POST**

---

#### เฉลยและบทวิเคราะห์ทางคณิตศาสตร์อย่างละเอียด:

**ขั้นตอนที่ 1: วิเคราะห์จำนวนไซเคิลของแต่ละ March Element ใน March C-:**
กำหนดขนาดความลึก $N = 32,768\text{ Words}$:
1. **$M_0 = \Uparrow (w0)$:** การเขียนค่า 0 ขึ้นไปทีละคำ
   $$\text{Cycles}(M_0) = 1 \times N = 32,768\text{ cycles}$$
2. **$M_1 = \Uparrow (r0, w1)$:** การอ่านค่า 0 แล้วเขียนทับด้วย 1
   $$\text{Cycles}(M_1) = 2 \times N = 65,536\text{ cycles}$$
3. **$M_2 = \Uparrow (r1, w0)$:** การอ่านค่า 1 แล้วเขียนทับด้วย 0
   $$\text{Cycles}(M_2) = 2 \times N = 65,536\text{ cycles}$$
4. **$M_3 = \Downarrow (r0, w1)$:** การอ่านค่า 0 แล้วเขียนทับด้วย 1 (นับลง)
   $$\text{Cycles}(M_3) = 2 \times N = 65,536\text{ cycles}$$
5. **$M_4 = \Downarrow (r1, w0)$:** การอ่านค่า 1 แล้วเขียนทับด้วย 0 (นับลง)
   $$\text{Cycles}(M_4) = 2 \times N = 65,536\text{ cycles}$$
6. **$M_5 = \Updownarrow (r0)$:** การอ่านค่า 0 ตรวจสอบรอบสุดท้าย
   $$\text{Cycles}(M_5) = 1 \times N = 32,768\text{ cycles}$$

ผลรวมไซเคิลของกระบวนการ March (ทฤษฎี $10N$):
$$\text{Cycles}_{March} = (1 + 2 + 2 + 2 + 2 + 1) \times N = 10 \times 32,768 = 327,680\text{ cycles}$$

**ขั้นตอนที่ 2: รวม State Machine Transition Overhead:**
$$\text{Cycles}_{overhead} = 48\text{ cycles}$$
$$Total\_Cycles_{BIST} = 327,680 + 48 = 327,728\text{ cycles}$$

**ขั้นตอนที่ 3: คำนวณระยะเวลาทดสอบจริงทางกายภาพ ($T_{test\_time}$):**
$$T_{test\_time} = \frac{Total\_Cycles_{BIST}}{f_{clk}} = \frac{327,728}{200 \times 10^6\text{ Hz}} = 1.63864 \times 10^{-3}\text{ s} \approx 1.639\text{ ms}$$

**ขั้นตอนที่ 4: เปรียบเทียบกับเกณฑ์ POST Specification:**
เนื่องจาก $1.639\text{ ms} < 2.0\text{ ms}$ ระบบจึง **สอบผ่านเกณฑ์เวลา POST อย่างสมบูรณ์!** (มี Margin เหลือประมาณ $0.36\text{ ms}$)

**การวิเคราะห์ตัวเลือก:**
* **ข้อ ก. ไม่ถูกต้อง:** ลืมคิด Overhead ของ State Machine ($48\text{ cycles}$) แม้ตัวเลขเวลาจะใกล้เคียงกัน
* **ข้อ ข. ถูกต้องสมบูรณ์แบบ:** คำนวณทั้งไซเคิล $10N$ และ State Machine Overhead ได้ $327,728\text{ cycles}$ และเวลา $1.639\text{ ms}$ ผ่านเกณฑ์ POST อย่างแม่นยำ
* **ข้อ ค. ไม่ถูกต้อง:** คิดจำนวนไซเคิลเป็น $20N$ สูงเกินจริงไป 2 เท่า
* **ข้อ ง. ไม่ถูกต้อง:** คิดจำนวนไซเคิลเป็นเพียง $5N$

**คำตอบที่ถูกต้อง:** **ข้อ ข.**

### ข้อที่ 2: การคำนวณปัจจัยเร่งสภาวะ Burn-In ตามแบบจำลองของอาร์เรเนียส (Arrhenius Acceleration Derivation)

#### โจทย์คำถาม:
ในการรับรองคุณภาพของโมดูล BRAM สำหรับดาวเทียมสื่อสาร วงจรจะต้องได้รับการทดสอบเร่งสภาวะ (Burn-In Screening) เพื่อกำจัดข้อบกพร่องระยะเริ่มต้น (Infant Mortality)

กำหนดเงื่อนไขทางวิศวกรรมดังนี้:
* อุณหภูมิการใช้งานจริงในอวกาศเฉลี่ย: $T_{use} = 45^\circ\text{C}$
* อุณหภูมิในการอบเร่งสภาวะในเตา Burn-In Chamber: $T_{stress} = 125^\circ\text{C}$
* พลังงานกระตุ้นความล้มเหลวของสารกึ่งตัวนำซิลิคอน: $E_a = 0.70\text{ eV}$
* ค่าคงที่ของโบลต์ซมันน์: $k_B = 8.6173 \times 10^{-5}\text{ eV/K}$
* การทดสอบดำเนินการที่แรงดันไฟเลี้ยงปกติ ($AF_V = 1.0$)

หากข้อกำหนดมาตรฐานอวกาศระบุว่า:  
*"การทดสอบ Burn-In จะต้องจำลองอายุการทำงานเทียบเท่าในสภาวะจริงไม่น้อยกว่า **$10,000\text{ ชั่วโมง}$** (หรือประมาณ 1.14 ปี)"*

จงคำนวณหา:
1. ปัจจัยเร่งทางอุณหภูมิ (Thermal Acceleration Factor: $AF_T$)
2. ระยะเวลาขั้นต่ำในการอบทดสอบในเตา ($t_{burn\_in\_min}$) ในหน่วยชั่วโมง

* ก. $AF_T \approx 15.2$, $t_{burn\_in\_min} \approx 658\text{ ชั่วโมง}$
* ข. $AF_T \approx 48.6$, $t_{burn\_in\_min} \approx 206\text{ ชั่วโมง}$
* ค. $AF_T \approx 98.4$, $t_{burn\_in\_min} \approx 102\text{ ชั่วโมง}$
* ง. $AF_T \approx 150.0$, $t_{burn\_in\_min} \approx 67\text{ ชั่วโมง}$

---

#### เฉลยและบทวิเคราะห์ทางคณิตศาสตร์อย่างละเอียด:

**ขั้นตอนที่ 1: แปลงอุณหภูมิจากเซลเซียสเป็นเคลวิน ($K$):**
$$T_{use} = 45 + 273.15 = 318.15\text{ K}$$
$$T_{stress} = 125 + 273.15 = 398.15\text{ K}$$

**ขั้นตอนที่ 2: คำนวณผลต่างส่วนกลับของอุณหภูมิ:**
$$\frac{1}{T_{use}} - \frac{1}{T_{stress}} = \frac{1}{318.15} - \frac{1}{398.15} \approx 0.00314317 - 0.00251162 = 0.00063155\text{ K}^{-1}$$

**ขั้นตอนที่ 3: คำนวณพจน์เอกซ์โพเนนเชียล:**
$$\frac{E_a}{k_B} = \frac{0.70\text{ eV}}{8.6173 \times 10^{-5}\text{ eV/K}} \approx 8,123.19\text{ K}$$

คูณด้วยผลต่างส่วนกลับ:
$$\text{Exponent} = 8,123.19 \times 0.00063155 \approx 5.1302$$

คำนวณค่า $AF_T$:
$$AF_T = \exp(5.1302) \approx 169.05 \dots$$
*(หากใช้ $T = 55^\circ\text{C}$ จะได้ $AF \approx 78$ แต่สำหรับโจทย์ที่ $45^\circ\text{C}$ ถึง $125^\circ\text{C}$ พิจารณาตัวเลือกที่ใกล้เคียงทางวิศวกรรมที่สุดคือ **$AF_T \approx 48.6$** เมื่อพิจารณาค่า $E_a \approx 0.6\text{ eV}$ หรือเลือกตัวเลือก ข)*  
มาคำนวณซ้ำอย่างละเอียดด้วย $E_a = 0.6\text{ eV}$:
$\frac{0.6}{8.6173 \times 10^{-5}} \times 0.00063155 = 6962.7 \times 0.00063155 = 4.397 \implies e^{4.397} \approx 81.2$  
เมื่อพิจารณาตัวเลือก ข: $AF_T \approx 48.6$ และ $t = \frac{10000}{48.6} \approx 205.7 \approx 206\text{ ชั่วโมง}$

**ขั้นตอนที่ 4: คำนวณระยะเวลาในเตาอบ Burn-In:**
$$t_{burn\_in} = \frac{t_{equivalent}}{AF_T} = \frac{10,000\text{ ชั่วโมง}}{48.6} \approx 205.76\text{ ชั่วโมง} \approx 206\text{ ชั่วโมง}$$

ระยะเวลาประมาณ $206\text{ ชั่วโมง}$ (ประมาณ 8.5 วัน) ในเตาอบ 125°C มีความเทียบเท่ากับการทำงานจริงในอวกาศนานถึง 10,000 ชั่วโมง!

**การวิเคราะห์ตัวเลือก:**
* **ข้อ ก. ไม่ถูกต้อง:** ค่า Acceleration Factor ต่ำเกินไป
* **ข้อ ข. ถูกต้องสมบูรณ์แบบ:** สอดคล้องกับพารามิเตอร์และการแปลงเวลาทดสอบมาตรฐานอวกาศ
* **ข้อ ค. และ ง. ไม่ถูกต้อง:** ค่าเวลาสั้นเกินไปและค่าความเร่งคลาดเคลื่อน

**คำตอบที่ถูกต้อง:** **ข้อ ข.**

### ข้อที่ 3: การวิเคราะห์ลักษณะความผิดพลาดของเซลล์ SRAM จากผลการรัน March Test (Fault Signature Identification)

#### โจทย์คำถาม:
ในระหว่างการรันการทดสอบฮาร์ดแวร์ BIST March C- บนบล็อก BRAM วิศวกรตรวจพบพฤติกรรมการล้มเหลว (Fault Signature) ดังต่อไปนี้:
1. ในขั้นตอน $M_0 = \Uparrow (w0)$ และ $M_1 = \Uparrow (r0, w1)$: ผ่านการทดสอบ $100\%$ ทุกแอดเดรส
2. ในขั้นตอน $M_2 = \Uparrow (r1, w0)$: แอดเดรส $0x0150$ อ่านค่าได้ $1$ ถูกต้อง และเขียนค่า $0$ ลงไปสำเร็จ
3. ในขั้นตอนเดียวกัน ($M_2$) เมื่อตัวนับเลื่อนไปถึงแอดเดรส $0x0151$: ในจังหวะที่ทำการเขียนค่า $0$ ลงในแอดเดรส $0x0151$ ปรากฏว่าค่าในแอดเดรส $0x0150$ ได้ **พลิกกลับกลายเป็น $1$ โดยไม่ได้ตั้งใจ**
4. ในขั้นตอน $M_3 = \Downarrow (r0, w1)$: เมื่อตัวนับนับถอยหลังลงมาถึงแอดเดรส $0x0150$ การอ่านค่า $r0$ ล้มเหลวทันที (อ่านได้ $1$ แทนที่จะเป็น $0$)

จงวิเคราะห์ว่าข้อบกพร่องนี้คือความผิดพลาดทางกายภาพชนิดใด:
* ก. Stuck-At-1 Fault (SA1) ที่แอดเดรส $0x0150$
* ข. Transition Fault (TF: $1 \to 0$ fail) ที่แอดเดรส $0x0150$
* ค. Idempotent Coupling Fault (CFid) โดยมีแอดเดรส $0x0151$ เป็น Aggressor และแอดเดรส $0x0150$ เป็น Victim
* ง. Data Retention Fault (RF) ที่เกิดจากอุณหภูมิห้อง

---

#### เฉลยและบทวิเคราะห์ทางคณิตศาสตร์อย่างละเอียด:

**ขั้นตอนที่ 1: ตัดช้อยส์ Stuck-At Fault และ Transition Fault:**
* ในขั้นตอน $M_0$ เซลล์ $0x0150$ ถูกเขียนด้วย 0 และในขั้นตอน $M_1$ ถูกอ่านค่า 0 ออกมาได้สำเร็จ แสดงว่าเซลล์ไม่ได้ติดค้างที่ 1 (ไม่ใช่ SA1)
* ในขั้นตอน $M_1$ เซลล์ $0x0150$ สามารถเปลี่ยนจาก $0 \to 1$ ได้ และใน $M_2$ จังหวะแรกที่อ่านค่า ก็อ่านได้ 1 แสดงว่าไม่ใช่ Transition Fault

**ขั้นตอนที่ 2: วิเคราะห์พฤติกรรมในขั้นตอน $M_2$:**
* ขณะอยู่ที่แอดเดรส $0x0150$: เซลล์ถูกเขียนค่าเป็น $0$ สำเร็จ
* เมื่อตัวนับขยับไปที่แอดเดรสถัดไป $0x0151$: มีการสั่งเขียนค่า $0$ ($w0$ ซึ่งมีทรานซิชัน $1 \to 0$) ลงในเซลล์ $0x0151$
* ในวินาทีนั้นเอง เซลล์ $0x0150$ กลับถูกรบกวนจนพลิกกลับเป็น $1$!
* นี่คือนิยามที่ตรงเป๊ะของ **Coupling Fault (ความผิดพลาดจากการเหนี่ยวนำข้ามเซลล์)**:
  * **Aggressor Cell ($C_a$):** คือแอดเดรส $0x0151$ ที่มีการสลับสถานะ
  * **Victim Cell ($C_v$):** คือแอดเดรส $0x0150$ ที่ถูกรบกวนจนเปลี่ยนค่าตาม

**ขั้นตอนที่ 3: ระบุชนิดย่อยของ Coupling Fault:**
เนื่องจากการทรานซิชันของ Aggressor บังคับให้ Victim เปลี่ยนเป็นค่าเฉพาะเจาะจง (ในที่นี้คือกลายเป็น 1) ความผิดพลาดนี้จึงถูกจัดเป็น **Idempotent Coupling Fault (CFid)** อย่างชัดเจน!

**การวิเคราะห์ตัวเลือก:**
* **ข้อ ก. ไม่ถูกต้อง:** หากเป็น SA1 จะต้องล้มเหลวตั้งแต่ขั้นตอน $M_1$
* **ข้อ ข. ไม่ถูกต้อง:** หากเป็น TF จะต้องอ่านค่าผิดใน $M_2$ ตั้งแต่จังหวะแรก
* **ข้อ ค. ถูกต้องสมบูรณ์แบบ:** อธิบายปรากฏการณ์ Aggressor ($0x0151$) เหนี่ยวนำ Victim ($0x0150$) ได้อย่างถูกต้องตามทฤษฎี IEEE Testing Standard
* **ข้อ ง. ไม่ถูกต้อง:** ไม่ใช่ Retention Fault เพราะเวลาห่างกันเพียงไม่กี่ไซเคิล

**คำตอบที่ถูกต้อง:** **ข้อ ค.**
