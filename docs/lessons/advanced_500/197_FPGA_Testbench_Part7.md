## 1. ทฤษฎีวิศวกรรมเชิงลึก (高度なエンジニアリング理論)

แม้ว่าการจำลองวงจรในคอมพิวเตอร์ (Software Simulation ทั้ง UVM และ Gate-Level Simulation) จะมีความแม่นยำสูงเพียงใด แต่ก็มีข้อจำกัดทางกายภาพที่ไม่อาจก้าวข้ามได้ นั่นคือ **"The 1,000,000x Speed Gap"**: การจำลองสัญญาณนาฬิกา $200\text{ MHz}$ บนซอฟต์แวร์จำลองวงจรขนาดใหญ่ มักทำความเร็วได้เพียงไม่กี่สิบถึงไม่กี่ร้อยกิโลเฮิรตซ์ (10 kHz – 100 kHz) การรันระบบให้ทำงานจริงเพียง 1 วินาทีในโลกแห่งความจริง อาจต้องใช้เวลารันบนคอมพิวเตอร์นานถึงหลายสัปดาห์หรือเป็นเดือน!

ยิ่งไปกว่านั้น ปรากฏการณ์ในระบบกายภาพ เช่น การตอบสนองของมอเตอร์ไฟฟ้า, วงจรไฮดรอลิก, คลื่นวิทยุสะท้อน, หรือการสั่นสะเทือนทางกล ไม่สามารถสร้างแบบจำลองทางคณิตศาสตร์ที่ครอบคลุมสภาวะแวดล้อมได้ 100%

วิศวกรระดับ Senior/Principal FPGA จึงต้องใช้สองเทคโนโลยีขั้นสูงในการตรวจสอบบนฮาร์ดแวร์จริง:
1. **Hardware-in-the-Loop (HIL):** การนำชิป FPGA ตัวจริงไปเชื่อมต่อกับแบบจำลองโรงงานเสมือนจริง (Real-Time Plant Simulator) ที่ทำงานแบบเรียลไทม์ระดับไมโครวินาที
2. **In-System Logic Analysis (ILA / SignalTap):** การฝังตัวตรวจจับสัญญาณดิจิทัล (Embedded Logic Analyzer) เข้าไปในเนื้อซิลิคอนของ FPGA เพื่อดักจับพฤติกรรมจริงที่ความเร็วสัญญาณนาฬิกาเต็มพิกัด

### 1.1 สถาปัตยกรรมภายในของ Integrated Logic Analyzer (ILA Microarchitecture)

ILA (เช่น AMD/Xilinx Vivado ILA หรือ Intel Quartus SignalTap) ไม่ใช่เวทมนตร์ แต่เป็น **วงจรดิจิทัลที่สังเคราะห์ขึ้นจากทรัพยากรจริงของ FPGA (BRAM, LUTs, Flip-Flops)** โดยมีโครงสร้างหลัก 3 ส่วน:

#### 1. Circular Sample Buffer (BRAM-Based FIFO)
- สัญญาณที่ถูกเลือกเป็น Probe จะถูกบันทึกค่าลงใน Block RAM ทุกๆ รอบสัญญาณนาฬิกาของระบบ ($clk_{sample}$)
- เมื่อตัวนับแอดเดรสวิ่งชนเพดานความลึก ($Depth = 2^K$) มันจะวนกลับมาเขียนทับข้อมูลเก่าที่แอดเดรส 0 เสมอ (Circular Ring Buffer)
- เมื่อเกิดเหตุการณ์ Trigger:
  - หากตั้งค่า **Trigger Position = 10% (Pre-trigger):** ILA จะหยุดบันทึกหลังจากนั้น 90% ของความลึก ทำให้เรามองเห็นข้อมูลประวัติศาสตร์ *ก่อนเกิดเหตุการณ์* ได้ 10% และ *หลังเกิดเหตุการณ์* ได้ 90%

#### 2. Advanced Multi-Stage Trigger Sequencer
ILA ระดับสูงไม่ได้ตรวจจับเพียงระดับสัญญาณ $0$ หรือ $1$ แบบธรรมดา แต่มี Finite State Machine (FSM) ภายในที่สามารถตั้งเงื่อนไขแบบลูกโซ่หลายขั้นตอน:
$$\text{Trigger Condition: } (State_0: A == 1) \xrightarrow{\text{then after 4 cycles}} (State_1: B == 0 \wedge C == 1) \xrightarrow{\text{within 16 cycles}} \mathbf{FIRE\_TRIGGER}$$

#### 3. Storage Qualification (ตัวกรองการบันทึกข้อมูล)
หากบันทึกข้อมูลทุกไซเคิล บัฟเฟอร์ขนาด 8,192 ช่องจะเต็มภายในเวลาเพียง $40.96\ \mu\text{s}$ (ที่คล็อก 200 MHz)  
**Storage Qualification** คือลอจิกที่สั่งให้ ILA บันทึกข้อมูลเฉพาะไซเคิลที่สัญญาณเงื่อนไขเป็นจริงเท่านั้น เช่น:
$$\text{Sample Enable: } \mathbf{valid\_in} == 1 \wedge \mathbf{ready\_in} == 1$$
วิธีนี้ทำให้บัฟเฟอร์ขนาดเท่าเดิมสามารถครอบคลุมช่วงเวลาการทำงานจริงของระบบได้ยาวนานขึ้นเป็นหลายนาทีหรือหลายชั่วโมง!

### 1.2 ข้อจำกัดทางกายภาพและสมการหน่วงเวลาของระบบ HIL (Closed-Loop Latency Math)

ในระบบ Closed-Loop Hardware-in-the-Loop เสถียรภาพของระบบควบคุมแบบป้อนกลับ (Stability Margin) ขึ้นอยู่กับ **เวลารวมในการประมวลผลทั้งลูป (Round-Trip Loop Latency: $T_{RTT}$)**

$$T_{RTT} = t_{DUT\_calc} + t_{Tx\_comm} + t_{Plant\_calc} + t_{Rx\_comm} + t_{DAC/ADC}$$

#### กฎเกณฑ์ความเสถียร (Control Loop Stability Invariant):
สำหรับระบบควบคุมดิจิทัลที่มีความถี่ในการสุ่มสัญญาณ $f_s = \frac{1}{T_s}$:
$$T_{RTT} \le T_s \times \Phi_{margin}$$
โดยที่ $\Phi_{margin} \le 0.25$ (ไม่เกิน 25% ของคาบการสุ่ม เพื่อป้องกัน Phase Margin ตกจนเกิดการแกว่ง / Instability Oscillation)

หากค่าหน่วงเวลา $T_{RTT}$ มีค่าสูงเกินไป จะเกิดการเลื่อนเฟสของสัญญาณป้อนกลับ (Phase Lag):
$$\theta_{lag} = 2\pi \cdot f_{bandwidth} \cdot T_{RTT} \quad [\text{radians}]$$
ซึ่งทำให้แบบจำลองเสมือนบนบอร์ดทดสอบ HIL ไม่สามารถสะท้อนพฤติกรรมจริงของเครื่องจักรกลในโรงงานได้อย่างถูกต้อง

### 1.3 ปัญหาทางวิศวกรรม: JTAG Bandwidth Bottleneck & Timing Closure Impact

1. **JTAG Readout Bottleneck:**
   การเชื่อมต่อระหว่างบอร์ด FPGA กับเครื่องคอมพิวเตอร์ผ่านสาย JTAG ทำงานที่ความถี่สัญญาณนาฬิกา $f_{TCK} \approx 10\text{ MHz} - 30\text{ MHz}$  
   เวลาในการดาวน์โหลดข้อมูลจาก ILA Buffer ($Depth$ ตัวอย่าง, ความกว้างโพรบ $W$ บิต) ขึ้นอยู่กับ:
   $$t_{download} = \frac{Depth \times W}{f_{TCK} \times \eta_{JTAG}}$$
   เมื่อ $\eta_{JTAG} \approx 0.6$ (ประสิทธิภาพโปรโตคอล)  
   หากตั้ง $Depth = 131,072$ และ $W = 256$ บิต จะต้องใช้เวลาถ่ายโอนข้อมูลเกือบ **2 วินาทีต่อการทริกเกอร์ 1 ครั้ง** จึงไม่สามารถดักจับเหตุการณ์ต่อเนื่องแบบ Real-Time Streaming ได้
2. **Timing Closure Degradation from Debug Nets:**
   การแทรกสัญญาณ Probe เข้าไปยังแกน ILA จะเพิ่ม Fan-out ให้กับสายสัญญาณ High-Speed ภายในชิป ซึ่งอาจทำให้เส้นทางวิกฤต (Critical Path) เดิมที่เคยผ่าน Timing กลายเป็นเกิด Setup Violation ทันทีที่ใส่คอร์ ILA ลงไป

### 1.4 RTL / Vivado Design Constraint Code: Master ILA Core Integration

```systemverilog
//=============================================================================
// Module: dsp_plant_controller_top
// Description: Industrial Closed-Loop Controller with Native ILA Debug Core
// Standards: IEEE 1149.1 JTAG / Vivado In-System Logic Analyzer Framework
//=============================================================================

`timescale 1ns / 1ps

module dsp_plant_controller_top (
    input  logic        sys_clk,       // 200 MHz System Clock
    input  logic        sys_rst_n,     // Active-low asynchronous reset
    input  logic        sensor_valid,  // Plant sensor data valid
    input  logic [15:0] sensor_adc_in, // Raw ADC sample from Plant
    output logic [15:0] dac_pwm_out,   // Actuator control output
    output logic        trip_alarm     // Emergency stop trigger
);

    // Controller Internal Registers & Signals
    logic signed [15:0] error_val;
    logic signed [31:0] pid_accum;
    logic signed [15:0] control_effort;
    logic [7:0]         state_fsm;
    logic               storage_qual_en;

    // FSM States
    localparam FSM_IDLE   = 8'h01;
    localparam FSM_SAMPLE = 8'h02;
    localparam FSM_CALC   = 8'h04;
    localparam FSM_ACT    = 8'h08;
    localparam FSM_TRIP   = 8'h80;

    // Control Loop Execution
    always_ff @(posedge sys_clk or negedge sys_rst_n) begin
        if (!sys_rst_n) begin
            error_val      <= '0;
            pid_accum      <= '0;
            control_effort <= '0;
            state_fsm      <= FSM_IDLE;
            dac_pwm_out    <= '0;
            trip_alarm     <= 1'b0;
        end else begin
            case (state_fsm)
                FSM_IDLE: begin
                    if (sensor_valid) state_fsm <= FSM_SAMPLE;
                end
                FSM_SAMPLE: begin
                    error_val <= 16'h2000 - sensor_adc_in; // Setpoint = 0x2000
                    state_fsm <= FSM_CALC;
                end
                FSM_CALC: begin
                    pid_accum <= pid_accum + (error_val * 4);
                    // Check for extreme condition (Over-pressure / Runaway)
                    if (sensor_adc_in > 16'h3E00) begin
                        state_fsm  <= FSM_TRIP;
                        trip_alarm <= 1'b1;
                    end else begin
                        control_effort <= error_val + pid_accum[23:8];
                        state_fsm      <= FSM_ACT;
                    end
                end
                FSM_ACT: begin
                    dac_pwm_out <= control_effort;
                    state_fsm   <= FSM_IDLE;
                end
                FSM_TRIP: begin
                    dac_pwm_out <= 16'h0000; // Safe clamp
                    // Latch trip condition
                end
            endcase
        end
    end

    // Storage Qualification: บันทึกเฉพาะรอบที่มีการคำนวณจริง ข้ามช่วง IDLE
    assign storage_qual_en = (state_fsm != FSM_IDLE);

    //=========================================================================
    // VIVADO INTEGRATED LOGIC ANALYZER (ILA) NATIVE CORE INSTANTIATION
    //=========================================================================
    // นำสัญญาณที่สำคัญเชื่อมเข้า Probe ของ ILA
    // ใน Vivado IP Catalog ให้สร้าง ILA Core: Depth = 4096, 6 Probes
`ifdef USE_IN_SYSTEM_ILA
    ila_controller_debug u_ila (
        .clk    (sys_clk),              // Sampling clock (200 MHz)
        .probe0 (sensor_adc_in),        // [15:0] Raw Input
        .probe1 (dac_pwm_out),          // [15:0] Output Command
        .probe2 (error_val),            // [15:0] Error
        .probe3 (state_fsm),            // [7:0]  Current FSM
        .probe4 (trip_alarm),           // [0:0]  Emergency Flag
        .probe5 (storage_qual_en)       // [0:0]  Sample Storage Qualification
    );
`endif

endmodule
```

## 2. ทริคหน้างาน OJT แบบ Step-by-Step (現場の実践テクニック)

### กรณีศึกษาความเสียหายจริงในภาคสนาม (失敗事例 - Shippai Jirei)
**ระบบตัวควบคุมไฮดรอลิกและแรงผลักของหัวเจาะอุโมงค์รถไฟฟ้าใต้ดินขนาดยักษ์ (Tunnel Boring Machine - TBM Hydraulic Controller FPGA)** เกิดปัญหาหยุดทำงานฉุกเฉินแบบสุ่ม (Intermittent Emergency Trip Shutdown): ทุกครั้งที่หัวเจาะกดกระทบกับชั้นหินแกรนิตแข็งพิเศษ หัวเจาะจะตัดการทำงานทันทีโดยไม่มีรหัสข้อผิดพลาดที่ชัดเจนบนหน้าจอมอนิเตอร์ การจำลองบนคอมพิวเตอร์ในออฟฟิศไม่สามารถทำให้เกิดปัญหานี้ได้เนื่องจากขาดแรงสั่นสะเทือนทางกลและพลศาสตร์ของน้ำมันไฮดรอลิกจริง ทีมงานจึงนำบอร์ดทดสอบไปวัดสัญญาณหน้างาน แต่เนื่องจากการตั้งค่า ILA ไม่ถูกต้อง บัฟเฟอร์ถูกเติมเต็มด้วยสัญญาณรบกวนจากการเด้งของสายโพรบสปริง (Spring Pogo Pin Contact Bounce) ทำให้ระบบขุดเจาะต้องหยุดชะงักนานถึง 14 วัน คิดเป็นค่าปรับความล่าช้าของโครงการก่อสร้างวันละ 150,000 ดอลลาร์ รวมมูลค่าความเสียหายกว่า 2.1 ล้านดอลลาร์สหรัฐ

### การวิเคราะห์หาสาเหตุรากเหง้า (5 Whys Root Cause Analysis)

1. **ทำไมหัวเจาะอุโมงค์จึงสั่งตัดการทำงานฉุกเฉินเมื่อเจาะชั้นหินแข็ง?**
   - *คำตอบ:* ตรรกะตรวจจับแรงดันน้ำมันไฮดรอลิกบน FPGA รายงานว่าเกิดแรงดันกระชากเกินขีดจำกัดสูงสุด (Spurious Pressure Spike Trip)
2. **ทำไมตรรกะจึงรายงานแรงดันเกินทั้งๆ ที่วาล์วระบายแรงดันยังไม่เปิด?**
   - *คำตอบ:* เกิดสัญญาณรบกวนความถี่สูง (EMI Noise) จากมอเตอร์ปั๊มไฮดรอลิกวิ่งเข้าสู่สายส่งสัญญาณ ADC รั่วไหลข้ามแดนคล็อก
3. **ทำไมการต่อ In-System Logic Analyzer (ILA) หน้างานในครั้งแรกจึงจับสาเหตุไม่ได้?**
   - *คำตอบ:* วิศวกรตั้งค่า ILA แบบบันทึกต่อเนื่องทุกไซเคิลโดยไม่ได้เปิด **Storage Qualification** ทำให้บัฟเฟอร์ขนาด 4,096 คำ เต็มไปด้วยข้อมูลที่สถานะปกติในเวลาเพียง 20 ไมโครวินาที ไม่ทันได้บันทึกจังหวะที่แรงดันกระชากจริง
4. **ทำไมสายวัดสัญญาณจากชุดทดสอบ (Test Fixture) จึงส่งสัญญาณหลอกเข้า ILA?**
   - *คำตอบ:* ขาโพรบแบบสปริง (Spring-loaded Pogo Pins) บนฟิกซ์เจอร์ทดสอบเสื่อมสภาพจากการสั่นสะเทือน มีค่าความเหนี่ยวนำแฝง ($L_{pin}$) สูง ทำให้เกิดการเด้งของกราวด์ (Ground Bounce) หลอกให้ Trigger ทำงานก่อนเวลาอันควร
5. **ทำไมกระบวนการตรวจแบบหน้างาน (Kenzu) จึงยอมให้ส่งมอบเครื่องทดสอบนี้?**
   - *คำตอบ:* ขาดขั้นตอนการตรวจสอบ **In-System Instrumentation Standard Operating Procedure (SOP)** สำหรับการทดสอบในสภาพแวดล้อมที่มีการสั่นสะเทือนรุนแรง

### คู่มือปฏิบัติการตรวจสอบ OJT หน้างาน: กลยุทธ์การใช้งาน ILA และ HIL อย่างมีประสิทธิภาพ

1. **Step 1: การใช้ Storage Qualification เพื่อประหยัดพื้นที่ BRAM (Preserving Trace Depth)**
   - อย่าบันทึกทุกไซเคิลของสัญญาณนาฬิกา
   - กำหนดให้ ILA เก็บข้อมูลเฉพาะเมื่อมีเหตุการณ์สำคัญเกิดขึ้น เช่น:
     `storage_qualification_condition = (adc_ready == 1 && state != IDLE);`
   - วิธีนี้ช่วยขยายระยะเวลาในการสังเกตการณ์พฤติกรรมได้มากกว่า 1,000 เท่า ด้วยหน่วยความจำ BRAM เท่าเดิม
2. **Step 2: การตั้งค่า Multi-Stage Trigger เพื่อขจัด False Trigger**
   - หลีกเลี่ยงการใช้ Trigger ชั้นเดียวที่อิงตามระดับสัญญาณเดี่ยว
   - ตั้งค่า Trigger เป็นลำดับ 2 ขั้นตอน (Sequencer):
     - Stage 1: รอจนกระทั่งระบบเข้าสู่โหมดการเจาะจริง (`state == DRILLING`)
     - Stage 2: ตรวจจับเมื่อค่าความดันสูงเกินเกณฑ์ติดต่อกันอย่างน้อย 4 ไซเคิล (`pressure > THRESHOLD [* 4]`)
3. **Step 3: การบำรุงรักษาและตรวจสอบ Spring Pogo Pin Fixture**
   - ในสภาพแวดล้อมโรงงาน ต้องตรวจสอบแรงกดของสปริง (Contact Force) ไม่ให้ต่ำกว่า $1.5\text{ N}$ ต่อพิน
   - ใช้สายกราวด์สั้นแบบ Coaxial หรือจัดวางพินแบบ Ground-Signal-Ground (G-S-G) เพื่อลด Inductance แฝง ป้องกันปัญหา Ground Bounce หลอกสัญญาณทริกเกอร์

## 4. ควิซวิเคราะห์ปัญหาระดับวิศวกรอาวุโส (上級技術クイズ)

### คำถามที่ 1: การคำนวณการใช้ทรัพยากร Block RAM สำหรับ ILA Core ภายในชิป

ในการออกแบบระบบฝัง ILA Core ลงบน FPGA สถาปัตยกรรม UltraScale+ เพื่อตรวจสอบสัญญาณภายในวงจรประมวลผลสัญญาณดิจิทัล:
- จำนวนสัญญาณ Probe ทั้งหมด: $W_{total} = 192\text{ บิต}$ (รวมบัสข้อมูลและสัญญาณควบคุม)
- ความลึกของบัฟเฟอร์ตัวอย่างที่ต้องการ (Sample Depth): $D = 16,384\text{ ตัวอย่าง}$ ($16\text{K samples}$)
- ทรัพยากรฮาร์ดแวร์: ชิปใช้โมดูล BRAM แบบมาตรฐาน **RAMB36E2** (ความจุโมดูลละ $36\text{ Kbits}$ หรือ $36,864\text{ บิต}$)
- โครงสร้างคอนฟิกของ RAMB36E2 ในโหมด True Dual-Port สามารถจัดสรรความกว้างสูงสุดได้ $72\text{ บิต} \times 512\text{ คำ}$ หรือในโหมดลึกสูงสุด $1\text{ บิต} \times 32,768\text{ คำ}$ หรือโหมดมาตรฐาน $36\text{ บิต} \times 1,024\text{ คำ}$

จงคำนวณหาจำนวนก้อน **Block RAM 36K (RAMB36E2)** ขั้นต่ำสุดทางทฤษฎีที่ต้องจัดสรรให้กับ ILA Core ตัวนี้:

- **A)** $16$ ก้อน
- **B)** $64$ ก้อน
- **C)** $86$ ก้อน
- **D)** $96$ ก้อน

---

#### เฉลยและคำอธิบายทางคณิตศาสตร์อย่างละเอียด

**คำตอบที่ถูกต้องคือ: C) $86$ ก้อน**

**การคำนวณและบทพิสูจน์ทางวิศวกรรม:**
1. คำนวณปริมาณหน่วยความจำบิตทั้งหมดที่จำเป็นสำหรับจัดเก็บข้อมูลของ ILA:
   $$Bits_{total} = W_{total} \times D = 192\text{ บิต} \times 16,384\text{ คำ} = 3,145,728\text{ บิต}$$
2. คำนวณความจุต่อ 1 ก้อน RAMB36E2:
   - บล็อก RAMB36 มีความจุสุทธิสำหรับเก็บข้อมูลผู้ใช้ (User Data Payload) เท่ากับ:
     $$Cap_{BRAM} = 36\text{ Kbits} = 36 \times 1024\text{ บิต} = 36,864\text{ บิต}$$
3. คำนวณจำนวน BRAM ทางทฤษฎีตามปริมาณบิตรวม:
   $$N_{BRAM\_ideal} = \frac{Bits_{total}}{Cap_{BRAM}} = \frac{3,145,728}{36,864} \approx 85.333\text{ ก้อน}$$
   เนื่องจากไม่สามารถแบ่งเสี้ยวของ BRAM ก้อนฮาร์ดแวร์ได้ จึงต้องปัดเศษขึ้นเป็นจำนวนเต็ม:
   $$N_{BRAM} = \lceil 85.333 \rceil = \mathbf{86\text{ ก้อน}}$$
4. การตรวจสอบเชิงโครงสร้างตาราง (Aspect Ratio Matrix Check):
   - เพื่อให้ได้ความลึก $16,384$ คำ ($16\text{K}$) แต่ละเส้นทางความลึกของ BRAM จะต้องใช้ RAMB36 ที่คอนฟิกในโหมดลึก เช่น $2\text{ บิต} \times 16,384\text{ คำ}$ (ใช้ $1$ RAMB36 ต่อ $2$ บิต)
   - หากใช้ $2$ บิตต่อก้อน สำหรับโพรบขนาด $192$ บิต จะต้องใช้:
     $$N_{blocks} = \frac{192\text{ บิต}}{2\text{ บิต/ก้อน}} = 96\text{ ก้อน}$$
   - แต่ในเครื่องมือ Vivado Core Generator สามารถแบ่งพาร์ทิชันย่อยด้วยโหมดผสมและ Cascading ทำให้จำนวน BRAM ขั้นต่ำสุดที่ถูกจองตามขีดจำกัดบิตจริงคือ **86 ถึง 96 ก้อน** ขึ้นอยู่กับประสิทธิภาพการจัดสรร Routing แต่ในเชิงขีดจำกัดทางทฤษฎีขั้นต่ำสุดของเซลล์ซิลิคอนคือ **86 ก้อน**

**การวิเคราะห์ตัวเลือกอื่น:**
- **ข้อ A ผิด:** $16$ ก้อน ไม่เพียงพอ เก็บข้อมูลได้เพียง $\approx 590\text{ Kbits}$
- **ข้อ B ผิด:** $64$ ก้อน เก็บข้อมูลได้เพียง $2,359,296\text{ บิต}$ (ขาดไปอีกเกือบ $1$ ล้านบิต)
- **ข้อ D ผิด:** $96$ ก้อน เป็นการจัดสรรแบบ Fixed 2-bit slicing โดยไม่มีการปรับแต่งแชร์เซกเมนต์

### คำถามที่ 2: การคำนวณระยะเวลาในการดาวน์โหลดข้อมูล ILA ผ่านคอขวด JTAG

วิศวกรทำการ Capture สัญญาณความเร็วสูงด้วย ILA Core โดยมีพารามิเตอร์ดังนี้:
- ความกว้างสัญญาณโพรบรวม: $W = 128\text{ บิต}$
- ความลึกของบัฟเฟอร์: $Depth = 32,768\text{ ตัวอย่าง}$ ($32\text{K}$)
- ความถี่สัญญาณนาฬิกาของสาย JTAG (TCK Frequency): $f_{TCK} = 15\text{ MHz}$
- ค่าโอเวอร์เฮดของโพรโตคอล JTAG Scan Chain, Shift-DR States, และ Packet Encapsulation ทำให้มีประสิทธิภาพการส่งข้อมูลจริง: $\eta_{eff} = 65\%$

จงคำนวณหาเวลาที่โปรแกรม Vivado Hardware Manager ต้องใช้ในการดึงข้อมูล Waveform ชุดนี้ออกจากชิป FPGA ผ่านสาย JTAG เข้าสู่หน้าจอคอมพิวเตอร์:

- **A)** $t_{readout} \approx 0.14\text{ วินาที}$
- **B)** $t_{readout} \approx 0.43\text{ วินาที}$
- **C)** $t_{readout} \approx 0.86\text{ วินาที}$
- **D)** $t_{readout} \approx 1.72\text{ วินาที}$

---

#### เฉลยและคำอธิบายทางคณิตศาสตร์อย่างละเอียด

**คำตอบที่ถูกต้องคือ: B) $t_{readout} \approx 0.43\text{ วินาที}$**

**การคำนวณและบทพิสูจน์ทางวิศวกรรม:**
1. คำนวณปริมาณข้อมูลดิบทั้งหมดที่ต้องเลื่อน (Shift) ออกจากชิปผ่านสาย TDO:
   $$Bits_{raw} = W \times Depth = 128\text{ บิต} \times 32,768 = 4,194,304\text{ บิต}$$
2. คำนวณอัตราการถ่ายโอนข้อมูลประสิทธิผลของสาย JTAG ต่อวินาที (Effective Throughput $R_{eff}$):
   $$R_{eff} = f_{TCK} \times \eta_{eff} = 15,000,000\text{ บิต/วินาที} \times 0.65 = 9,750,000\text{ บิต/วินาที}$$
3. คำนวณเวลาที่ใช้ในการอ่านข้อมูลทั้งหมด:
   $$t_{readout} = \frac{Bits_{raw}}{R_{eff}} = \frac{4,194,304\text{ บิต}}{9,750,000\text{ บิต/วินาที}} \approx 0.43018\text{ วินาที}$$
   หรือประมาณ **0.43 วินาที** (เกือบครึ่งวินาที)

**การวิเคราะห์ตัวเลือกอื่น:**
- **ข้อ A ผิด:** $0.14$ วินาที คิดจากกรณีที่มีประสิทธิภาพสมมุติ $200\%$ หรือคิดโพรบแคบเพียง 32 บิต
- **ข้อ C ผิด:** $0.86$ วินาที เกิดจากการลืมคูณประสิทธิภาพ หรือคิดความถี่ TCK เพียงครึ่งเดียว ($7.5\text{ MHz}$)
- **ข้อ D ผิด:** $1.72$ วินาที สูงเกินจริงไป 4 เท่า

### คำถามที่ 3: ปัญหา Ground Bounce จากค่าความเหนี่ยวนำแฝงของ Spring Pogo Pin Fixture

ในการทดสอบ HIL ด้วยชุดทดสอบ Spring-loaded Pogo Pin Fixture สัญญาณบัสข้อมูลขนานจำนวน $N = 32$ เส้น มีการสลับสถานะพร้อมกันจาก $1 \to 0$ (Simultaneous Switching Outputs: SSO) ด้วยความเร็วสูง  
- อัตราการเปลี่ยนแปลงของกระแสต่อเส้น: $\frac{di}{dt} = 25\text{ mA / 1.0 ns} = 2.5 \times 10^7\text{ A/s}$ ต่อพิน  
- แต่ละพินสปริงมีความเหนี่ยวนำปรสิต (Parasitic Inductance): $L_{pin} = 4.0\text{ nH}$  
- บนชุดฟิกซ์เจอร์มีพินกราวด์ (Ground Return Pogo Pin) ร่วมกันเพียง $N_{gnd} = 2$ พิน สำหรับบัสข้อมูลทั้ง 32 เส้นนี้

จงคำนวณหาค่าแรงดันกระดอนของกราวด์ชั่วขณะ (Peak Ground Bounce Voltage: $V_{bounce}$) บนวงจรกราวด์ของฟิกซ์เจอร์นี้:

- **A)** $V_{bounce} = 0.40\text{ V}$
- **B)** $V_{bounce} = 0.80\text{ V}$
- **C)** $V_{bounce} = 1.60\text{ V}$
- **D)** $V_{bounce} = 3.20\text{ V}$

---

#### เฉลยและคำอธิบายทางคณิตศาสตร์อย่างละเอียด

**คำตอบที่ถูกต้องคือ: C) $V_{bounce} = 1.60\text{ V}$**

**การคำนวณและบทพิสูจน์ทางวิศวกรรม:**
1. คำนวณอัตราการเปลี่ยนแปลงของกระแสรวมทั้งหมดที่ไหลกลับผ่านโครงข่ายกราวด์:
   - มีเส้นสัญญาณสลับพร้อมกัน $N = 32$ เส้น
   - แต่ละเส้นมีอัตราการเปลี่ยนกระแส $\frac{di}{dt} = 2.5 \times 10^7\text{ A/s}$
   $$\left(\frac{dI}{dt}\right)_{total} = N \times \left(\frac{di}{dt}\right) = 32 \times (2.5 \times 10^7\text{ A/s}) = 8.0 \times 10^8\text{ A/s}$$
2. คำนวณค่าความเหนี่ยวนำรวมของเส้นทางไหลกลับของกราวด์ ($L_{gnd\_eff}$):
   - มีพินกราวด์ต่อขนานกันจำนวน $N_{gnd} = 2$ พิน
   $$L_{gnd\_eff} = \frac{L_{pin}}{N_{gnd}} = \frac{4.0\text{ nH}}{2} = 2.0\text{ nH} = 2.0 \times 10^{-9}\text{ H}$$
3. คำนวณค่าแรงดัน Ground Bounce ตามกฎการเหนี่ยวนำของฟาราเดย์:
   $$V_{bounce} = L_{gnd\_eff} \times \left(\frac{dI}{dt}\right)_{total}$$
   แทนค่าตัวเลข:
   $$V_{bounce} = (2.0 \times 10^{-9}\text{ H}) \times (8.0 \times 10^8\text{ A/s}) = \mathbf{1.60\text{ V}}$$
4. **การวิเคราะห์ผลกระทบทางวิศวกรรม:**
   แรงดัน Ground Bounce สูงถึง **1.60 V** ในระบบลอจิกแรงดัน $1.8\text{ V}$ หรือ $3.3\text{ V}$ นั้นรุนแรงเพียงพอที่จะทำให้ระดับลอจิก $0$ ยกตัวสูงขึ้นทะลุผ่านขีดจำกัด $V_{IL}$ กลายเป็นลอจิก $1$ ชั่วขณะ ส่งผลให้เกิดการกระดอนหลอกตา (False Glitch Trigger) บน ILA หรือทำให้ DUT รีเซ็ตตัวเองทันที! เพื่อป้องกันปัญหานี้ อัตราส่วนพิน Signal ต่อ Ground ควรอยู่ที่ $1:1$ หรืออย่างน้อย $2:1$ ไม่ใช่ $16:1$

**การวิเคราะห์ตัวเลือกอื่น:**
- **ข้อ A ผิด:** คิดว่ามีพินกราวด์ 8 พิน
- **ข้อ B ผิด:** คิดว่ามีพินกราวด์ 4 พิน
- **ข้อ D ผิด:** คำนวณโดยใช้พินกราวด์เพียงพินเดียว ($N_{gnd} = 1$)
