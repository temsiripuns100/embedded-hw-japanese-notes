## 1. ทฤษฎีวิศวกรรมเชิงลึก (高度なエンジニアリング理論)

### 1.1 สถาปัตยกรรมชิปแบบหลายดาย (Stacked Silicon Interconnect - SSI Technology)
ในชิป FPGA ขนาดใหญ่ระดับเรือธง เช่น Xilinx Virtex UltraScale+ (VU9P, VU13P) และ Versal Premium แผ่นชิปไม่ได้ถูกสร้างขึ้นจากผลึกซิลิคอนก้อนเดียวแบบดั้งเดิม (Monolithic Die) อีกต่อไป เนื่องจากข้อจำกัดด้านขนาดหน้ากากการผลิต (Reticle Limit) และอัตราผลผลิต (Yield Rate)

ผู้ผลิตจึงใช้เทคโนโลยี **Stacked Silicon Interconnect (SSI)** โดยนำแผ่นซิลิคอนย่อยหลายชิ้น เรียกว่า **Super Logic Regions (SLRs)** มาวางเคียงข้างกันบนแผ่นฐานซิลิคอนอินเทอร์โพเซอร์แบบพาสซีฟ (Passive Silicon Interposer) และเชื่อมโยงหากันด้วยเสาไมโครบัมพ์ (Micro-bumps) และรูเจาะทะลุซิลิคอน (Through-Silicon Vias - TSVs):

```
                   สถาปัตยกรรม STACKED SILICON INTERCONNECT (SSI)
                   
     ┌───────────────────────┐   ┌───────────────────────┐   ┌───────────────────────┐
     │  SLR 2 (Upper Die)    │   │  SLR 1 (Middle Die)   │   │  SLR 0 (Lower Die)    │
     │  Logic, BRAM, DSP     │   │  Logic, BRAM, DSP     │   │  Logic, BRAM, DSP     │
     └───────────┬───────────┘   └───────────┬───────────┘   └───────────┬───────────┘
                 │ (Micro-bumps)             │ (Micro-bumps)             │ (Micro-bumps)
     ════════════╧═══════════════════════════╧═══════════════════════════╧════════════
                     PASSIVE SILICON INTERPOSER (ชั้นสายโลหะเชื่อมต่อระหว่างดาย)
                        Super Long Lines (SLLs) & Laguna Routing Sites
     ═════════════════════════════════════════════════════════════════════════════════
```

### 1.2 ฟิสิกส์ของการข้ามรอยต่อ SLR และสถานีเชื่อมต่อ Laguna Sites

เส้นทางเชื่อมต่อที่วิ่งข้ามระหว่าง SLR เรียกว่า **Super Long Lines (SLLs)** ซึ่งมีลักษณะทางกายภาพที่แตกต่างจากสายส่งภายใน Fabric อย่างสิ้นเชิง:
* มีความจุไฟฟ้าแฝงสูงเป็นพิเศษ ($C_{interposer} \gg C_{fabric}$) จากรอยต่อไมโครบัมพ์และสายโลหะยาวบนอินเทอร์โพเซอร์
* ในแต่ละขอบรอยต่อระหว่าง SLR จะมีสาย SLL ติดตั้งอยู่จำกัด (ประมาณ $15,000 - 25,000\text{ เส้น}$ ต่อรอยต่อ)

```
                 กายวิภาคของ LAGUNA SITE ระหว่างสอง SLRs
                 
     [ SLR 1: Sending Die ]
     Internal Fabric ──► [ Laguna TX Register ] (ฟลิปฟล็อปเฉพาะทางที่ริมขอบดาย)
                                    │
                                    ▼ (Micro-bump Pad)
     ═══════════════════════════════╪═══════════════════════════════ (SLR Boundary)
                                    │ (Interposer Metal SLL)
                                    ▼ (Micro-bump Pad)
     [ SLR 0: Receiving Die ]
     Internal Fabric ◄── [ Laguna RX Register ] (ฟลิปฟล็อปเฉพาะทางที่ริมขอบดาย)
```

#### กฎเหล็กของการส่งสัญญาณข้าม SLR (The SLR Crossing Commandments):
1. **ห้ามส่งสัญญาณแบบ Combinational Logic ข้าม SLR เด็ดขาด!**  
   ความล่าช้าในการวิ่งข้ามอินเทอร์โพเซอร์แบบไม่มีฟลิปฟล็อปกั้นมีค่าสูงถึง **$2.2\text{ ns} - 3.8\text{ ns}$** ซึ่งจะกลืนกินคาบเวลาของสัญญาณนาฬิกาทั้งหมดจนเกิด Setup Violation ทันที!
2. **ต้องเป็นการข้ามแบบ Register-to-Register ผ่าน Laguna Sites เท่านั้น:**  
   สัญญาณต้องออกจากฟลิปฟล็อปตัวขับ วิ่งเข้าสู่ **Laguna TX Register** $\to$ ข้ามอินเทอร์โพเซอร์ $\to$ เข้าสู่ **Laguna RX Register**
3. **การจัดสรรงบประมาณ Latency (Pipelining Budget):**  
   สำหรับการทำงานที่ความถี่ $\ge 300\text{ MHz}$ **ต้องจัดสรร Latency สำหรับการข้าม SLR ไว้อย่างน้อย $1 - 2\text{ ไซเคิล}$ เสมอ!**

### 1.3 ทฤษฎีการจัดผังพื้นที่ (Floorplanning) และการนิยาม Pblocks

**Floorplanning** คือกระบวนการที่วิศวกรเข้าควบคุมการจัดวางตำแหน่งเชิงกายภาพของโมดูลในระบบให้อยู่ในขอบเขตพิกัดที่กำหนด โดยใช้เครื่องมือ **Physical Block (Pblock)**:

```
                    การจัดผัง PBLOCKS ข้าม SUPER LOGIC REGIONS
                    
   ┌─────────────────────────────────────────────────────────────┐
   │ SLR 2: [ Pblock_PCIe_DMA ] ──► [ Pblock_Host_Interface ]   │
   ├─────────────────────────────────────────────────────────────┤
   │ SLR 1: [ Pblock_Neural_Network_Compute_Core (CNN/LLM) ]     │
   ├─────────────────────────────────────────────────────────────┤
   │ SLR 0: [ Pblock_100G_MAC ] ──► [ Pblock_Packet_Parser ]     │
   └─────────────────────────────────────────────────────────────┘
```

#### ประโยชน์ของการทำ Floorplanning:
1. **การกักขังลอจิก (Logic Confinement):** ควบคุมให้ลอจิกที่มีการเชื่อมโยงความหนาแน่นสูง (High-Density Clusters) เกาะกลุ่มอยู่ด้วยกันภายใน SLR เดียวกัน
2. **การควบคุมจุดตัดข้ามแดน (Boundary Cut Minimization):** ลดจำนวนสายสัญญาณที่ต้องวิ่งข้ามรอยต่อของ SLR ให้เหลือน้อยที่สุดตามกฎของเรนท์ (Rent's Rule)
3. **การหลีกเลี่ยงคอขวด Pin Pinching:** ป้องกันไม่ให้เราเตอร์บีบลอจิกไปวางในซอกแคบๆ ระหว่างคอลัมน์ BRAM/DSP ซึ่งจะทำให้เกิด Routing Congestion

#### คำสั่ง XDC สำหรับสร้างและปรับขนาด Pblock:
```tcl
# สร้าง Pblock และเพิ่มเซลล์ในลำดับชั้นเข้าสู่ Pblock
create_pblock pblock_packet_proc
add_cells_to_pblock [get_pblocks pblock_packet_proc] [get_cells -hierarchical u_packet_proc]

# กำหนดพิกัดทางกายภาพให้อยู่ภายใน SLR 0 เท่านั้น
resize_pblock [get_pblocks pblock_packet_proc] -add {CLOCKREGION_X0Y0:CLOCKREGION_X3Y1}

# กำหนดให้ห้ามนำลอจิกอื่นมาร่วมพื้นที่ (Exclusion)
set_property EXCLUDE_PLACEMENT TRUE [get_pblocks pblock_packet_proc]
```

### 1.4 การจัดการบัส AXI4 ข้าม SLR ด้วย AXI Register Slice

เมื่อบัสข้อมูลขนาดกว้าง เช่น บัส AXI4-Stream ขนาด $512\text{ บิต}$ (ซึ่งรวมสัญญาณ Data, Keep, Valid, Ready, Last มีสายสัญญาณมากกว่า $600\text{ เส้น}$) จำเป็นต้องเดินทางข้ามรอยต่อระหว่าง SLR:
* หากปล่อยให้เดินสายแบบไร้การควบคุม สายสัญญาณ 600 เส้นจะกินช่องทาง SLL จนแน่นขนัด
* ทางออกสากลคือการแทรกไอพี **AXI Register Slice** ในโหมด **Multi-SLR Crossing**:

```
                 สถาปัตยกรรม AXI REGISTER SLICE (MULTI-SLR MODE)
                 
    [ SLR 1: Master ]                                    [ SLR 0: Slave ]
    Master AXI Bus ──► [ Full Forward Reg ] ──► [ Laguna TX ]
                             ▲                      │ (SLLs)
                             │                      ▼
                       [ Auto Handshake ] ◄── [ Laguna RX ] ──► Slave AXI Bus
                       (คุม READY ย้อนกลับ)   [ Full Reverse Reg ]
```

โหมด Multi-SLR ของ AXI Register Slice จะทำการแทรกฟลิปฟล็อปแยกอิสระทั้งในทิศทาง Forward (VALID, DATA) และ Reverse (READY) ทำให้สายสัญญาณทั้งสองทิศทางถูกตัดตอนออกจากกันอย่างสมบูรณ์ ปลดล็อกให้บัส 512 บิตสามารถวิ่งข้าม Die ได้ที่ความถี่สูงกว่า **$400\text{ MHz} - 500\text{ MHz}$**!

## 2. ทริคหน้างาน OJT แบบ Step-by-Step (現場的事例)

### 2.1 กรณีศึกษาความล้มเหลวหน้างาน: การ์ด SmartNIC 200Gbps พังพินาศจากการลาก AXI Switch ข้ามรอยต่อ Die (SmartNIC Inter-SLR Crossing Catastrophe)

```
+----------------------------------------------------------------------------------------------------+
| กรณีศึกษาความล้มเหลวหน้างาน (現場の失敗事例)                                                                 |
| เหตุการณ์: การ์ดเชื่อมต่อเครือข่ายศูนย์ข้อมูลความเร็วสูง 200Gbps SmartNIC บน Virtex UltraScale+ VU9P (3 SLRs) |
| อาการ: ขั้นตอน Place & Route ล้มเหลวโดยสิ้นเชิงหลังจากรันไปนานกว่า 16 ชั่วโมง รายงานแสดง WNS = -3.42ns       |
|        เกิดความแออัดของสายสัญญาณระดับวิกฤต (Routing Congestion Level 7 - Severe Overflow) ตรงรอยต่อ SLR0/1   |
|        และมีสายสัญญาณมากกว่า 12,000 เส้นพยายามแย่งชิงช่องทาง SLL จนเราเตอร์หยุดทำงานและแจ้ง Fatal Error!     |
+----------------------------------------------------------------------------------------------------+
```

#### การวิเคราะห์หาสาเหตุรากเหง้าด้วยหลักการ 5 Whys (5 Whys Root Cause Analysis):

1. **ทำไมขั้นตอน Place & Route จึงเกิดความล้มเหลวและ WNS ติดลบถึง -3.42ns?**  
   *คำตอบ:* มีเส้นทางข้อมูลวิกฤตหลายพันเส้นทางที่ลากข้ามรอยต่อระหว่าง SLR0 และ SLR1 โดยมีเวลาหน่วงของสายส่งสูงถึง $4.8\text{ ns}$

2. **ทำไมเส้นทางข้าม SLR จึงมีความล่าช้าสูงถึง $4.8\text{ ns}$?**  
   *คำตอบ:* สัญญาณที่ข้ามรอยต่อเป็นวงจรคอมบิเนชันของสวิตช์มัลติเพล็กเซอร์ (AXI Crossbar Multiplexer) ที่ไม่มีฟลิปฟล็อปคั่นกลาง

3. **ทำไมวงจร AXI Switch จึงถูกวางพาดคาบเกี่ยวข้ามระหว่าง SLR0 และ SLR1?**  
   *คำตอบ:* ทีมออกแบบไม่ได้กำหนดข้อจำกัด Floorplanning (ไม่มี Pblock) ปล่อยให้ซอฟต์แวร์ Place & Route วางตำแหน่งเซลล์แบบอัตโนมัติ

4. **ทำไม Vivado จึงตัดสินใจวางวงจรสวิตช์คร่อมระหว่างสอง SLRs?**  
   *คำตอบ:* ซอฟต์แวร์พยายามเฉลี่ยความหนาแน่นของ Slice LUT ใน SLR0 ที่เกือบเต็ม ($85\%$) โดยผลักลอจิกครึ่งหนึ่งของสวิตช์ขึ้นไปไว้ใน SLR1 โดยไม่รู้ว่านี่คือรอยต่อระหว่างแผ่นซิลิคอนที่ต้องข้ามอินเทอร์โพเซอร์!

5. **ทำไมทีมงานจึงไม่ใช้ AXI Register Slice ในโหมด Multi-SLR?**  
   *คำตอบ:* วิศวกรผู้รับผิดชอบไม่เคยทำงานกับชิปขนาดใหญ่แบบ Multi-Die SSI มาก่อน คิดว่าชิป VU9P เป็นแผ่นซิลิคอนก้อนเดียวเหมือนชิปขนาดเล็ก จึงไม่ได้ออกแบบโครงสร้างการแบ่งสเตจไปป์ไลน์สำหรับข้าม Die ไว้ในสถาปัตยกรรมระดับบน!

### 2.3 คู่มือปฏิบัติงาน SOP: การออกแบบและปิดไทม์มิ่งข้าม Super Logic Regions (Multi-SLR SOP)

#### สเต็ปที่ 1: ตรวจสอบแผนผังโครงสร้าง SLR ของเบอร์ชิปที่เลือกใช้
* ตรวจสอบคู่มือ `UG575 (Packaging and Pinout)` หรือเปิด Device View ใน Vivado เพื่อดูว่าชิปมีกี่ SLR (เช่น VU9P มี 3 SLRs: SLR0, SLR1, SLR2)
* แบ่งสรรปันส่วนหน้าที่ของโมดูลหลักระดับท็อปให้สอดคล้องกับแต่ละ SLR ตั้งแต่ขั้นตอนร่างสถาปัตยกรรม

#### สเต็ปที่ 2: ล็อคโมดูลเข้าสู่ Pblocks ภายใน SLR เดียวอย่างเคร่งครัด
* สร้าง Pblock แยกสำหรับแต่ละโมดูล และบังคับให้อยู่ภายใน SLR เดียวกัน $100\%$:

```tcl
# ล็อค Engine ให้อยู่ใน SLR 1 เท่านั้น ห้ามล้นข้ามแดน
create_pblock pblock_crypto_engine
add_cells_to_pblock [get_pblocks pblock_crypto_engine] [get_cells -hierarchical u_crypto]
resize_pblock [get_pblocks pblock_crypto_engine] -add {CLOCKREGION_X0Y4:CLOCKREGION_X5Y7}
```

#### สเต็ปที่ 3: แทรก AXI Register Slice หรือ Pipeline Bridge บนเส้นทางข้ามแดนทุกเส้น
* เส้นทางใดๆ ที่จำเป็นต้องส่งสัญญาณข้ามระหว่าง SLR ต้องมี **ฟลิปฟล็อปไปป์ไลน์อย่างน้อย 2 สเตจ** กั้นกลางเสมอ
* กำหนดแอตทริบิวต์สั่งให้ Vivado นำฟลิปฟล็อปเหล่านี้ไปวางใน **Laguna Sites**:

```tcl
# สั่งให้ Vivado นำรีจิสเตอร์ข้ามแดนไปวางลงใน Laguna Hard Sites
set_property USER_SLL_REG TRUE [get_cells -hierarchical *slr_bridge_reg*]
```

#### สเต็ปที่ 4: ตรวจสอบรายงานการใช้งาน SLL Tracks (SLL Utilization Report)
* รันคำสั่งตรวจสอบความหนาแน่นของการข้ามอินเทอร์โพเซอร์:
  `report_slr_utilization -file slr_util.rpt`
* ตรวจสอบว่าจำนวนสายสัญญาณที่ข้ามรอยต่อในแต่ละจุด ต้องไม่เกิน **$60\% - 70\%$ ของช่องทาง SLL ทั้งหมด** เพื่อป้องกันปัญหา Routing Congestion

## 4. ควิซวิเคราะห์ปัญหาระดับวิศวกรอาวุโส (上級技術クイズ)

### ข้อที่ 1: การคำนวณ Latency และความถี่สูงสุดสำหรับการส่งข้อมูลข้ามรอยต่อ SLR

#### โจทย์คำถาม:
ในชิป Virtex UltraScale+ VU9P เส้นทางส่งข้อมูลระหว่างโมดูลใน SLR0 และ SLR1 มีความจำเป็นต้องข้ามรอยต่อของแผ่นซิลิคอนผ่านช่องทาง **Interposer SLL**

พารามิเตอร์ทางกายภาพของวงจร:
* ความล่าช้าของสายส่งภายใน Fabric จากจุดกำเนิดไปยัง Laguna TX Site: $T_{fabric\_tx} = 0.650\text{ ns}$
* ค่า Clock-to-Out ของ Laguna TX Register: $T_{cko\_laguna} = 0.280\text{ ns}$
* ความล่าช้าในการวิ่งข้ามสายส่งโลหะบน Silicon Interposer: $T_{sll\_wire} = 0.720\text{ ns}$
* ค่า Setup Time ของ Laguna RX Register: $T_{setup\_laguna} = 0.150\text{ ns}$
* ความล่าช้าของสายส่งจาก Laguna RX Site ไปยังวงจรประมวลผลปลายทางใน Fabric: $T_{fabric\_rx} = 0.850\text{ ns}$
* ค่า Clock Uncertainty และ Skew รวมข้าม SLR: $T_{skew\_unc} = 0.200\text{ ns}$

หากเปรียบเทียบ 2 สถาปัตยกรรม:
* **สถาปัตยกรรม A (1-Cycle Raw Crossing):** ส่งสัญญาณจาก Fabric ใน SLR0 ข้ามอินเทอร์โพเซอร์ไปยัง Fabric ใน SLR1 ภายในรอบสัญญาณนาฬิกาเดียว (ไม่มีการใช้ Laguna Registers คั่นกลาง) โดยมีความล่าช้ารวม $T_{total\_A} = T_{fabric\_tx} + T_{sll\_wire} + T_{fabric\_rx} + T_{overhead}$
* **สถาปัตยกรรม B (Dedicated Laguna Pipelined Crossing):** ใช้ Laguna TX และ Laguna RX Registers กั้นหัวท้าย โดยช่วงที่ข้ามอินเทอร์โพเซอร์ (TX $\to$ RX) ถูกตัดตอนเป็น 1 ไซเคิลอิสระ

จงคำนวณหา:
1. คาบเวลาขั้นต่ำ ($T_{period\_A}$) และความถี่สูงสุด ($F_{max\_A}$) ของสถาปัตยกรรม A
2. คาบเวลาขั้นต่ำ ($T_{period\_B}$) และความถี่สูงสุด ($F_{max\_B}$) ของช่วงข้ามแดนในสถาปัตยกรรม B
3. เปอร์เซ็นต์การเพิ่มขึ้นของความถี่ที่สถาปัตยกรรม B ทำได้เหนือกว่าสถาปัตยกรรม A

* ก. $F_{max\_A} = 344.83\text{ MHz}$, $F_{max\_B} = 740.74\text{ MHz}$, ความถี่เพิ่มขึ้น $114.8\%$
* ข. $F_{max\_A} = 384.61\text{ MHz}$, $F_{max\_B} = 500.00\text{ MHz}$, ความถี่เพิ่มขึ้น $30.0\%$
* ค. $F_{max\_A} = 277.78\text{ MHz}$, $F_{max\_B} = 740.74\text{ MHz}$, ความถี่เพิ่มขึ้น $166.7\%$
* ง. $F_{max\_A} = 344.83\text{ MHz}$, $F_{max\_B} = 555.55\text{ MHz}$, ความถี่เพิ่มขึ้น $61.1\%$

---

#### เฉลยและบทวิเคราะห์ทางคณิตศาสตร์อย่างละเอียด:

**ขั้นตอนที่ 1: วิเคราะห์สถาปัตยกรรม A (1-Cycle Raw Crossing ข้าม Fabric สู่ Fabric):**
ความล่าช้าสะสมทั้งหมดใน 1 ไซเคิล:
$$T_{data\_A} = T_{fabric\_tx} + T_{sll\_wire} + T_{fabric\_rx} = 0.650\text{ ns} + 0.720\text{ ns} + 0.850\text{ ns} = 2.220\text{ ns}$$
เมื่อรวม Overhead ทางเวลา (สมมติ $T_{cko} + T_{setup} + T_{skew\_unc} = 0.350 + 0.130 + 0.200 = 0.680\text{ ns}$):
$$T_{period\_A} = T_{data\_A} + T_{overhead} = 2.220\text{ ns} + 0.680\text{ ns} = 2.900\text{ ns}$$
คำนวณความถี่สูงสุด:
$$F_{max\_A} = \frac{1}{2.900 \times 10^{-9}\text{ s}} \approx 344,827,586\text{ Hz} \approx 344.83\text{ MHz}$$

**ขั้นตอนที่ 2: วิเคราะห์สถาปัตยกรรม B (ข้ามผ่าน Laguna TX $\to$ Laguna RX):**
ในสถาปัตยกรรม B เส้นทางข้ามอินเทอร์โพเซอร์ถูกตัดตอนให้มีเฉพาะระหว่าง Laguna TX และ RX เท่านั้น:
ความล่าช้าของ Data Path ระหว่าง TX $\to$ RX:
$$T_{data\_B} = T_{sll\_wire} = 0.720\text{ ns}$$
เมื่อรวม Overhead ของเซลล์ Laguna:
$$T_{period\_B} = T_{cko\_laguna} + T_{sll\_wire} + T_{setup\_laguna} + T_{skew\_unc}$$
$$T_{period\_B} = 0.280\text{ ns} + 0.720\text{ ns} + 0.150\text{ ns} + 0.200\text{ ns} = 1.350\text{ ns}$$
คำนวณความถี่สูงสุด:
$$F_{max\_B} = \frac{1}{1.350 \times 10^{-9}\text{ s}} \approx 740,740,740\text{ Hz} \approx 740.74\text{ MHz}$$

**ขั้นตอนที่ 3: คำนวณเปอร์เซ็นต์การเพิ่มขึ้นของความถี่:**
$$\text{Speedup} = \frac{F_{max\_B} - F_{max\_A}}{F_{max\_A}} \times 100\% = \frac{740.74 - 344.83}{344.83} \times 100\% = \frac{395.91}{344.83} \times 100\% \approx 114.81\% \approx 114.8\%$$

การใช้สถานี Laguna Registers กั้นหัวท้ายช่วยปลดล็อกให้ความถี่ของช่วงข้ามแดนพุ่งขึ้นจาก $344.83\text{ MHz}$ เป็น **$740.74\text{ MHz}$ (เร็วขึ้นถึง $114.8\%$)** ขจัดคอขวดของการข้ามแผ่นซิลิคอนได้อย่างเด็ดขาด!

**การวิเคราะห์ตัวเลือก:**
* **ข้อ ก. ถูกต้องสมบูรณ์แบบ:** ตัวเลข $344.83\text{ MHz}$, $740.74\text{ MHz}$ และอัตราการเพิ่มขึ้น $114.8\%$ ตรงตามหลักวิชาการ $100\%$
* **ข้อ ข. ไม่ถูกต้อง:** ประมาณการความถี่ B ต่ำเกินไป
* **ข้อ ค. ไม่ถูกต้อง:** คาบเวลา A คำนวณผิดพลาด
* **ข้อ ง. ไม่ถูกต้อง:** ตัวเลขความเร็วคลาดเคลื่อน

**คำตอบที่ถูกต้อง:** **ข้อ ก.**

### ข้อที่ 2: การคำนวณความจุช่องทาง SLL และการบริหารจัดการแบนด์วิดท์ข้ามแดน

#### โจทย์คำถาม:
ในชิป Virtex UltraScale+ รอยต่อระหว่าง SLR0 และ SLR1 มีจำนวนช่องทางเชื่อมต่อ Super Long Lines (SLLs) ทางกายภาพทั้งหมด **$N_{SLL\_total} = 23,040\text{ เส้น}$**

ระบบประมวลผลเครือข่ายต้องการส่งข้อมูลข้ามรอยต่อนี้ประกอบด้วย:
1. บัส AXI4-Stream ขนาดกว้าง $512\text{ bits}$ จำนวน $16\text{ ช่องสัญญาณ}$ (แต่ละช่องมีสายข้อมูลและสัญญาณควบคุมรวม $620\text{ เส้น}$)
2. บัสควบคุมสถานะแบบคู่ขนาน (Status Control Buses) รวมทั้งสิ้น $1,800\text{ เส้น}$

หากมาตรฐานวิศวกรรมการออกแบบขององค์กรระบุเกณฑ์ความปลอดภัยไว้ว่า:  
*"อัตราการใช้งานช่องทาง SLL (SLL Utilization Ratio) จะต้องไม่เกิน **$65.0\%$** เพื่อป้องกันสภาวะการแย่งชิงสายสัญญาณจนเกิด Placement & Routing Failure"*

จงคำนวณหา:
1. จำนวนสายสัญญาณรวมทั้งหมดที่ระบบต้องการส่งข้ามรอยต่อ ($Total\_Wires_{req}$)
2. อัตราส่วนการใช้งานช่องทาง SLL จริงที่เกิดขึ้น และระบุว่าผ่านเกณฑ์ความปลอดภัย $65\%$ หรือไม่
3. หากไม่ผ่านเกณฑ์ จะต้องปรับลดจำนวนบัส AXI4-Stream ลงเหลือกี่ช่องสัญญาณจึงจะทำให้อัตราการใช้งาน $\le 65.0\%$?

* ก. $Total\_Wires = 11,720\text{ เส้น}$, ใช้ไป $50.87\%$, ผ่านเกณฑ์ความปลอดภัย
* ข. $Total\_Wires = 11,720\text{ เส้น}$, ใช้ไป $50.87\%$, ไม่จำเป็นต้องลด
* ค. $Total\_Wires = 15,720\text{ เส้น}$, ใช้ไป $68.23\%$ (ไม่ผ่านเกณฑ์!), ต้องลด AXI ลงเหลือไม่เกิน 14 ช่อง
* ง. $Total\_Wires = 11,720\text{ เส้น}$, ใช้ไป $50.87\%$ (ผ่านเกณฑ์!), แต่ต้องลดเหลือ 8 ช่อง

#### เฉลยและบทวิเคราะห์ทางคณิตศาสตร์อย่างละเอียด:

**ขั้นตอนที่ 1: คำนวณจำนวนสายสัญญาณรวมที่ต้องการส่งข้ามรอยต่อ:**
* จำนวนสายจากบัส AXI4-Stream 16 ช่อง:
  $$Wires_{AXI} = 16 \times 620\text{ เส้น} = 9,920\text{ เส้น}$$
* จำนวนสายควบคุมสถานะ:
  $$Wires_{Control} = 1,800\text{ เส้น}$$
* ผลรวมสายสัญญาณทั้งหมด:
  $$Total\_Wires_{req} = 9,920 + 1,800 = 11,720\text{ เส้น}$$

**ขั้นตอนที่ 2: คำนวณอัตราส่วนการใช้งาน SLL (SLL Utilization):**
$$Utilization = \frac{Total\_Wires_{req}}{N_{SLL\_total}} \times 100\% = \frac{11,720}{23,040} \times 100\% \approx 50.868\% \approx 50.87\%$$
เปรียบเทียบกับเกณฑ์ความปลอดภัย:
$$50.87\% \le 65.00\%$$
ดังนั้น ระบบนี้ **สอบผ่านเกณฑ์ความปลอดภัยของ SLL อย่างสมบูรณ์!** (มี Margin เหลืออีกประมาณ $14.13\%$ หรือประมาณ 3,256 เส้น สำหรับการขยายระบบในอนาคต)

**การวิเคราะห์ตัวเลือก:**
* **ข้อ ก. ถูกต้องสมบูรณ์แบบ:** คำนวณสายรวมได้ 11,720 เส้น คิดเป็น $50.87\%$ และสรุปว่าผ่านเกณฑ์ได้อย่างถูกต้อง
* **ข้อ ข. คล้าย ก. แต่สรุปกำกวม**
* **ข้อ ค. ไม่ถูกต้อง:** คำนวณจำนวนสาย AXI ผิดพลาดทำให้ตัวเลขพุ่งไปถึง 15,720 เส้น
* **ข้อ ง. ไม่ถูกต้อง:** สรุปให้ลดทั้งๆ ที่ผ่านเกณฑ์แล้ว

**คำตอบที่ถูกต้อง:** **ข้อ ก.**

### ข้อที่ 3: การประเมินผลกระทบของปรากฏการณ์ Pin Pinching ใน Pblock Floorplanning

#### โจทย์คำถาม:
วิศวกรทำการกำหนดพื้นที่ Pblock สำหรับโมดูลถอดรหัสวิดีโอ โดยบีบพื้นที่ให้อยู่ในแถบแคบๆ ขนาดความกว้างเพียง $1\text{ Clock Region}$ ในแนวนอน แต่ยาว $4\text{ Clock Regions}$ ในแนวตั้ง (`CLOCKREGION_X2Y0:CLOCKREGION_X2Y3`)

จากการตรวจสอบโครงสร้างภายใน พบว่ามีโมดูลย่อย 2 ตัวที่ต้องสื่อสารกันด้วยบัสขนาดกว้าง $1,024\text{ bits}$ โดยโมดูล A ถูกวางที่ `X2Y0` และโมดูล B ถูกวางที่ `X2Y3`  
ระหว่างสองจุดนี้มีคอลัมน์ของบล็อก BRAM และ DSP ขวางกั้นอยู่ ทำให้ช่องทางเดินสายว่างในแนวตั้ง (Vertical Routing Channel) มีขนาดแคบมาก

ปรากฏการณ์นี้ในทางวิศวกรรม Floorplanning เรียกว่าอะไร และจะส่งผลกระทบอย่างไรต่อกระบวนการ Timing Closure:
* ก. เรียกว่า **Rent's Pinning Effect**, ช่วยให้สัญญาณเดินทางได้เร็วขึ้นเนื่องจากสายถูกบังคับให้ตรง
* ข. เรียกว่า **Pin Pinching (คอขวดการบีบอัดสายสัญญาณ)**, ส่งผลให้เราเตอร์เกิดความแออัดของสายส่งระดับรุนแรง (Severe Routing Congestion) ในช่องแคบแนวตั้ง และทำให้ค่าความล่าช้าของสายส่งพุ่งสูงจน WNS ติดลบ
* ค. เรียกว่า **Laguna Saturation**, ไม่มีผลกระทบต่อไทม์มิ่งเนื่องจากอยู่ใน SLR เดียวกัน
* ง. เรียกว่า **Clock Spine Contention**, ทำให้สัญญาณนาฬิกาหยุดเดิน

#### เฉลยและบทวิเคราะห์ทางคณิตศาสตร์อย่างละเอียด:

**ขั้นตอนที่ 1: วิเคราะห์ปรากฏการณ์ทางกายภาพ (Silicon Physics):**
* เมื่อวิศวกรกำหนดรูปร่างของ Pblock เป็นแถบผอมยาว (High Aspect Ratio Rectangle) ลอจิกจะถูกบีบให้สื่อสารกันผ่านช่องทางเดินสายที่แคบมาก
* ปรากฏการณ์นี้เรียกว่า **Pin Pinching (หรือ Routing Channel Narrowing)**
* บัสข้อมูลกว้างถึง 1,024 บิตต้องการสายไฟอย่างน้อย 1,024 เส้นวิ่งขนานกัน แต่ช่องแคบระหว่างคอลัมน์ฮาร์ดแมโครมีช่องทาง Routing Tracks ไม่เพียงพอ
* เราเตอร์จึงจำใจต้องขดสายไฟอ้อมไปทางอื่น (Extreme Route Detours) หรือเกิดความแออัดพุ่งสูงเกิน $100\%$ ส่งผลให้ความล่าช้าพุ่งสูงและทำให้เกิด **Setup Violation รุนแรง** จนปิดไทม์มิ่งไม่ลง!

**ขั้นตอนที่ 2: วิธีแก้ไขที่ถูกต้องตามหลัก Floorplanning:**
* รูปร่างของ Pblock ที่ดีควรมีสัดส่วนกว้างคูณยาวใกล้เคียงสี่เหลี่ยมจัตุรัส (**Aspect Ratio ใกล้เคียง 1.0**) เพื่อให้มีช่องทางเดินสายกระจายตัวได้รอบทิศทาง (Isotropic Routing Channels)

**การวิเคราะห์ตัวเลือก:**
* **ข้อ ก. ไม่ถูกต้อง:** ไม่มีปรากฏการณ์ชื่อนี้ และไม่ได้ทำให้เร็วขึ้น
* **ข้อ ข. ถูกต้องสมบูรณ์แบบ:** นิยามคำว่า Pin Pinching และอธิบายผลกระทบต่อ Routing Congestion และ Setup Violation ได้อย่างถูกต้องตามหลักวิศวกรรม
* **ข้อ ค. ไม่ถูกต้อง:** Laguna ใช้สำหรับการข้ามระหว่าง SLR ไม่เกี่ยวกับช่องแคบใน Fabric เดียวกัน
* **ข้อ ง. ไม่ถูกต้อง:** ไม่ได้ทำให้ Clock หยุดเดิน

**คำตอบที่ถูกต้อง:** **ข้อ ข.**
