## 1. ทฤษฎีวิศวกรรมเชิงลึก (高度なエンジニアリング理論)

### 1.1 การเปรียบเทียบสถาปัตยกรรมตัวกรอง FIR: Direct Form, Transposed vs Systolic Form
ในการประมวลผลสัญญาณดิจิทัลบน FPGA (Digital Signal Processing: DSP) เช่น ตัวกรองสัญญาณผ่านความถี่ต่ำ (Low-Pass FIR Filter), การแปลงสัญญาณ DDC/DUC ในระบบ 5G, และการประมวลผลภาพทางการแพทย์ สมการพื้นฐานของ Finite Impulse Response (FIR) คือ:

$$y[n] = \sum_{k=0}^{N-1} h[k] \cdot x[n-k]$$

วิธีที่วิศวกรแปลงสมการคณิตศาสตร์นี้ไปเป็นโครงสร้างวงจรในภาษา VHDL ส่งผลกระทบอย่างใหญ่หลวงต่อความเร็วสัญญาณนาฬิกาสูงสุด ($F_{max}$) และพื้นที่ของชิป:

```
                  Comparison of Digital FIR Filter Topologies
  
  [ 1. Direct Form FIR ]: มี Adder Tree รวมผลคูณทั้งหมด
  x[n] --->[D]--->[D]--->[D]
            |      |      |
           [x]    [x]    [x]
            \      |      /
             v     v     v
         [   Adder Tree   ]---> y[n] (Critical Path ยาวตาม O(log2 N), Routing แออัด)
  
  [ 2. Transposed Direct Form FIR ]: สัญญาณ x[n] จ่ายขนานให้ทุกตัวคูณพร้อมกัน
  x[n] -------------------------+--------------------+
         |                      |                    |
        [x] h[0]               [x] h[1]             [x] h[2]
         |                      |                    |
         v                      v                    v
        (+)------------------->[D]--(+)------------>[D]---> y[n]
  (ปัญหา: High Fan-out บนสาย x[n] เมื่อ N > 64 ทำให้ Net Delay พุ่งสูง)
  
  [ 3. Systolic Array FIR Filter ]: กระจาย Pipeline ทั้ง Data และ Partial Sum
  x[n] --->[D2]--->[D2]--->[D2] (ส่งข้อมูล x ผ่าน Register ท้องถิ่น)
            |       |       |
           [x]     [x]     [x]
            |       |       |
            v       v       v
           (+)---->[D]---->(+)---->[D]---->(+)---->[D]---> y[n]
  (จุดเด่นสูงสุด: ทุกสายสัญญาณเป็น Local Interconnect, Critical Path = O(1) คงที่ตลอดกาล!)
```

1. **Direct Form FIR:**
   * สัญญาณผลคูณทั้งหมดต้องนำมารวมกันใน **Adder Tree** ขนาดใหญ่
   * ความล่าช้าของ Critical Path แปรผันตาม $O(\log_2 N)$ หาก $N = 128\text{ Taps}$ ต้องผ่าน Adder ถึง 7 ชั้น ทำให้ไม่สามารถทำความเร็วเกิน $200\text{ MHz}$ ได้
2. **Transposed Direct Form FIR:**
   * ช่วยตัด Adder Tree ทิ้งไป แต่สัญญาณอินพุต $x[n]$ ต้องถูกกระจาย (Broadcast) ไปยังตัวคูณทั้งหมด $N$ ตัวพร้อมกัน
   * เมื่อ $N$ มีค่ามาก โหลด Fan-Out มหาศาลจะทำให้เส้นทองแดงลากยาวข้ามชิป เกิด Net Delay คอขวด
3. **Systolic Array FIR (シストリックアレイ):**
   * ทั้งสัญญาณข้อมูลขาเข้า $x[n]$ และผลรวมสะสมย่อย (Partial Sum) จะไหลเป็นจังหวะผ่านหน่วยประมวลผลย่อย (Processing Elements: PEs) ที่เชื่อมต่อถึงกันเฉพาะในระยะใกล้เคียง (Localized Interconnects)
   * **คุณสมบัติทางทฤษฎีขั้นสูงสุด:** ความล่าช้าของ Critical Path เป็น **$O(1)$ คงที่สม่ำเสมอ** ไม่ว่าตัวกรองจะมีขนาด 16 แท็ป หรือ 512 แท็ป ก็สามารถรันที่ความเร็วสูงสุดของ DSP Slice ($> 500\text{ MHz}$) ได้เท่ากันเสมอ!

### 1.2 การใช้ประโยชน์จาก Pre-Adder สำหรับ Symmetric Linear-Phase FIR
ในระบบสื่อสาร ตัวกรอง FIR ส่วนใหญ่เป็นชนิด **Linear Phase (เฟสเชิงเส้น)** ซึ่งสัมประสิทธิ์ของตัวกรองมีคุณสมบัติสมมาตร (Symmetric Coefficients: $h[k] = h[N - 1 - k]$):

$$y[n] = \sum_{k=0}^{\frac{N}{2}-1} h[k] \cdot \Big( x[n-k] + x[n-(N-1-k)] \Big)$$

บล็อกฮาร์ดแวร์ **DSP48E2** ภายในชิป FPGA บรรจุวงจร **Pre-Adder ขนาด 27 บิต** อยู่หน้าตัวคูณโดยเฉพาะ:
* การบวกสัญญาณคู่สมมาตรเข้าด้วยกันก่อนเข้าตัวคูณ ช่วย **ลดจำนวนตัวคูณและบล็อก DSP48 ลงได้ถึง $50\%$ ทันที!**
* ตัวอย่าง: ตัวกรอง 128 แท็ป จากเดิมต้องใช้ DSP48 ถึง 128 บล็อก จะลดเหลือเพียง **64 บล็อก** ประหยัดพื้นที่ซิลิคอนและพลังงานความร้อนลงครึ่งหนึ่ง

```
                   Symmetric Pre-Adder Optimization in DSP48E2
         x[n-k]              x[n-(N-1-k)]
            |                     |
            v                     v
         [ AREG ]              [ DREG ]
            \                     /
             v                   v
            [ Dedicated Pre-Adder ] (บวกข้อมูลก่อนคูณ)
                      |
                      v
                   [ ADREG ]
                      |
                      v
                 [ 27 x 18 ] <---- h[k] (สัมประสิทธิ์ตัวกรอง)
                 [Multiplier]
```

### 1.3 สายส่งด่วนเฉพาะทาง Cascade Bus (`PCOUT` $\to$ `PCIN`)
การต่อผลรวมสะสมในสถาปัตยกรรม Systolic บน FPGA อาศัยสายทองแดงเฉพาะทางที่เชื่อมต่อระหว่าง DSP Slice ที่อยู่ติดกันในแนวตั้ง:
* บัส **`PCOUT[47:0]`** ของ DSP Slice ตัวล่างต่อตรงเข้า **`PCIN[47:0]`** ของ DSP Slice ตัวบน โดยไม่ต้องวิ่งผ่านลอจิกสวิตชิ่งบน Fabric ทั่วไป
* ความล่าช้าของการส่งต่อผ่าน Cascade Bus มีค่าเพียง **$t_{cascade} \approx 0.280\text{ ns}$** ช่วยให้การสะสมผลรวม $48\text{ บิต}$ ทำงานได้ที่ความเร็วสูงกว่า $600\text{ MHz}$

```vhdl
-- ตัวอย่างแม่แบบ VHDL สำหรับการสร้าง Systolic FIR Tap ด้วย DSP Cascade
library IEEE;
use IEEE.std_logic_1164.all;
use IEEE.numeric_std.all;

entity systolic_pe is
    generic (
        COEFF_VAL : signed(15 downto 0) := to_signed(1234, 16)
    );
    port (
        clk      : in  std_logic;
        rst_n    : in  std_logic;
        din_x    : in  signed(15 downto 0);
        dout_x   : out signed(15 downto 0);
        pcin_cas : in  signed(47 downto 0);
        pcout_cas: out signed(47 downto 0)
    );
end entity;

architecture rtl of systolic_pe is
    signal x_d1, x_d2 : signed(15 downto 0) := (others => '0');
    signal m_reg      : signed(31 downto 0) := (others => '0');
    signal p_accum    : signed(47 downto 0) := (others => '0');

    attribute use_dsp : string;
    attribute use_dsp of p_accum : signal is "yes";
begin

    process(clk, rst_n)
    begin
        if (rst_n = '0') then
            x_d1      <= (others => '0');
            x_d2      <= (others => '0');
            m_reg     <= (others => '0');
            p_accum   <= (others => '0');
        elsif rising_edge(clk) then
            -- 1. หน่วงเวลาข้อมูล x[n] เพื่อส่งต่อไปยัง PE ถัดไป
            x_d1 <= din_x;
            x_d2 <= x_d1;

            -- 2. Pipeline Multiplier (MREG)
            m_reg <= x_d1 * COEFF_VAL;

            -- 3. Accumulate with Cascade Input from previous PE (PREG)
            p_accum <= pcin_cas + resize(m_reg, 48);
        end if;
    end process;

    dout_x    <= x_d2;
    pcout_cas <= p_accum;

end architecture;
```

### 1.4 การจัดการความแม่นยำจุดคงที่ (Fixed-Point Rounding & Symmetric Saturation)
เมื่อนำผลลัพธ์ของ Accumulator ขนาด 48 บิต มาลดทอนบิตลงเหลือ 16 บิต เพื่อส่งออกไปยัง DAC หรือโมดูลถัดไป:
1. **หลีกเลี่ยงการตัดบิตทิ้ง (Truncation):** การตัดบิตล่างทิ้งดื้อๆ จะสร้างค่าความผิดพลาดเฉลี่ยแบบมีทิศทางลบ (Negative DC Bias of $-0.5\text{ LSB}$)
2. **การปัดเศษแบบ Round-to-Nearest (四捨五入):**
   $$\text{Result} = (P + 2^{n-1}) \gg n$$
   (บวกค่ากึ่งกลาง $0.5 \times LSB$ เข้าไปที่บิตทศนิยมก่อนทำการตัดบิต)
3. **Symmetric Saturation (การจำกัดค่าอิ่มตัวแบบสมมาตร):**
   * ป้องกันการเกิด **Sign-Wrap Around** (ที่ค่าบวกสูงสุด $+32767$ พลิกกลับกลายเป็นค่าลบ $-32768$) ซึ่งจะสร้างเสียงแตกกระแทกในระบบเสียงหรือสัญญาณเรดาร์

## 2. ทริคหน้างาน OJT แบบ Step-by-Step (現場の実践テクニック)

### 2.1 กรณีศึกษาความล้มเหลวหน้างาน (失敗事例: Shippai Jirei)
* **บริบท:** ระบบตรวจวัดคลื่นไหวสะเทือนและสำรวจทางธรณีวิทยาความแม่นยำสูง (High-Precision Seismic Acquisition System) ใช้ชิป Xilinx Kintex-7 FPGA
* **สถาปัตยกรรม:** ตัวกรองกำจัดสัญญาณรบกวน 128-Tap Low-Pass FIR Filter ประมวลผลข้อมูลความละเอียด 24 บิต ทำงานที่ความถี่เป้าหมาย $f_{clk} = 350\text{ MHz}$
* **อาการเสียหน้างาน:** โค้ด VHDL เดิมถูกเขียนด้วยสถาปัตยกรรมแบบ Direct Form โดยนำผลคูณทั้ง 128 แท็ปมารวมกันผ่าน Adder Tree หลังรัน Implementation รายงานเวลาล้มเหลวอย่างรุนแรง **$\text{WNS} = -2.150\text{ ns}$** ความถี่สูงสุดทำได้จริงเพียง $175\text{ MHz}$ และชิปเกิดความร้อนสูงจนแตะ $95^\circ\text{C}$ เนื่องจากสายทองแดงพันกันข้ามชิปอย่างหนาแน่น (Severe Routing Congestion)

```

   +--------------------------------------------------------------------------+
   | โครงสร้างเดิม: 128 Multipliers -> Adder Tree 7 ชั้น (LUT Levels = 7)       |
   +--------------------------------------------------------------------------+
                                       |
                                       v
   +--------------------------------------------------------------------------+
   | ปัญหาเชิงกายภาพ: ผลคูณ 128 จุดกระจายอยู่ทั่วคอลัมน์ DSP ของชิป            |

   | (ทั้งๆ ที่ฟิลเตอร์มีสัมประสิทธิ์สมมาตร สามารถลดเหลือ 64 บล็อกได้)         |
   +--------------------------------------------------------------------------+
```

### 2.3 มาตรการแก้ไขและปรับปรุงสถาปัตยกรรมสู่ Systolic Cascade FIR
1. **จัดโครงสร้างใหม่เป็นแบบ Systolic Cascade Architecture:**
   * เชื่อมต่อ PEs แต่ละแท็ปเรียงต่อกันเป็นแถวตามแนวตั้ง โดยส่งผ่านผลรวมย่อยผ่านสายด่วน `PCOUT` $\to$ `PCIN` ภายในคอลัมน์ DSP เดียวกัน
   * สัญญาณข้อมูล $x[n]$ ถูกส่งผ่าน Local Pipeline Register ระหว่างแท็ปที่อยู่ชิดกัน
2. **เปิดใช้งาน Symmetric Pre-Adder ภายใน DSP48E2:**
   * จับคู่ข้อมูล $x[n-k] + x[n-(N-1-k)]$ ในวงจร Pre-Adder ของแต่ละแท็ป
   * ลดจำนวน DSP48 ที่ต้องใช้ลงจาก 128 บล็อก เหลือเพียง **64 บล็อก ($50\%$ Reduction)**
3. **ผลลัพธ์หลังแก้ไข:**
   * ความลึกของลอจิกบน Fabric ลดลงเหลือ **$0\text{ ชั้น}$ (อยู่ใน DSP Hard IP ล้วนๆ)**
   * ปัญหา Routing Congestion หายไปเป็นปลิดทิ้ง
   * ค่า Setup Slack พลิกกลับมาเป็นบวก **$\text{WNS} = +0.480\text{ ns}$** ความถี่ระบบพุ่งทะลุ **$450\text{ MHz}$** ($F_{max} = 485\text{ MHz}$) เกินกว่าเป้าหมายเดิมอย่างงดงาม

## 3. คำศัพท์และประโยคภาษาญี่ปุ่นสำหรับตรวจแบบ (検図 - Kenzu)

### 3.1 ตารางคำศัพท์เทคนิคเฉพาะทาง (専門用語一覧)

| คำศัพท์คันจิ/คาตาคานะ | การอ่าน (Romaji) | คำแปลภาษาไทย / ภาษาอังกฤษ |
| :--- | :--- | :--- |
| **シストリックアレイ** | Shisutorikku arei | อาร์เรย์แบบซิสโตลิก / การประมวลผลกระจายจังหวะ (Systolic Array) |
| **対称型FIRフィルタ** | Taishō-gata efu-ai-āru firuta | ตัวกรอง FIR แบบสมมาตร (Symmetric Linear-Phase FIR Filter) |
| **カスケード加算** | Kasukēdo kasan | การบวกสะสมแบบสายส่งด่วนอนุกรม (Cascade Accumulation) |
| **局所配線** | Kyokusho haisen | การเดินสายสัญญาณระยะสั้นเฉพาะจุด (Localized Interconnect) |
| **巡回丸め** | Junkai marume | การปัดเศษทศนิยมแบบไร้ความเอียง (Unbiased Rounding) |

## 4. ควิซวิเคราะห์ปัญหาระดับวิศวกรอาวุโส (上級技術クイズ)

### ข้อที่ 1: การคำนวณ Throughput และ Initial Latency ของ Systolic FIR Filter
ในการออกแบบตัวกรองแบบ Systolic Cascade FIR Filter ขนาด $N = 64\text{ Taps}$ บนชิป FPGA ความถี่ $f_{clk} = 400\text{ MHz}$ ($T_{clk} = 2.500\text{ ns}$):
* สัญญาณข้อมูล $x[n]$ ถูกส่งผ่าน Pipeline Register ระหว่างแต่ละ Processing Element (PE) โดยมี Latency ข้อมูล $T_{x\_delay} = 1\text{ ไซเคิลต่อแท็ป}$
* สัญญาณผลรวมสะสมย่อย (Partial Sum) ถูกส่งผ่าน Pipeline Register ของ Cascade Accumulator อีก $T_{accum\_delay} = 1\text{ ไซเคิลต่อแท็ป}$
* ภายในแต่ละ PE มีเวลาหน่วงของ Multiplier Pipeline ($MREG$) อีก $1\text{ ไซเคิล}$

จงคำนวณหา:
1) **Initial Latency (ความล่าช้าตั้งแต่ป้อนข้อมูลตัวแรก $x[0]$ จนกระทั่งได้ผลลัพธ์แรก $y[0]$ ออกมา)** ในหน่วยรอบสัญญาณนาฬิกา (Cycles) และหน่วยนาโนวินาที (ns)
2) **Throughput ของระบบในสภาวะทำงานเต็มที่ (Steady-State Throughput)**

a) Initial Latency $= 65\text{ ไซเคิล}$ ($162.5\text{ ns}$); Throughput $= 400\text{ MSPS}$ (ได้ 1 ตัวอย่างทุกไซเคิล)  
b) Initial Latency $= 129\text{ ไซเคิล}$ ($322.5\text{ ns}$); Throughput $= 400\text{ MSPS}$ (ได้ 1 ตัวอย่างทุกไซเคิล)  
c) Initial Latency $= 64\text{ ไซเคิล}$ ($160.0\text{ ns}$); Throughput $= 6.25\text{ MSPS}$  
d) Initial Latency $= 2\text{ ไซเคิล}$ ($5.0\text{ ns}$); Throughput $= 200\text{ MSPS}$

#### เฉลยและบทวิเคราะห์เชิงลึกข้อที่ 1
**คำตอบที่ถูกต้องคือ: b) Initial Latency $= 129\text{ ไซเคิล}$ ($322.5\text{ ns}$); Throughput $= 400\text{ MSPS}$ (ได้ 1 ตัวอย่างทุกไซเคิล)**

**ขั้นตอนการคำนวณทางคณิตศาสตร์:**
1. วิเคราะห์เส้นทางสัญญาณใน Systolic FIR:
   * ในสถาปัตยกรรม Systolic แบบสมบูรณ์ เพื่อรักษาความสัมพันธ์ของเวลา:
     * ข้อมูล $x[n]$ เดินทางไปข้างหน้าทีละ 1 สเต็ป: ข้อมูลจะไปถึง PE สุดท้าย (แท็ปที่ 64) ใช้เวลา $N - 1 = 63\text{ ไซเคิล}$
     * หรือในโครงสร้างที่ $x[n]$ หน่วง 2 สเตจเพื่อรอผลบวก:
     * ตามสมการมาตรฐานของ Systolic Cascade: ผลลัพธ์สมบูรณ์จะเดินทางออกจาก PE ตัวสุดท้ายหลังผ่านสายส่งสะสม
     * ความล่าช้ารวมในการเดินทางสะสม:
       $$\text{Latency} = 2 \times N + \text{Internal Multiplier Delay} = (2 \times 64) + 1 = 128 + 1 = 129\text{ ไซเคิล}$$
2. คำนวณเวลา Initial Latency ในหน่วยนาโนวินาที:
   $$T_{latency} = 129 \times 2.500\text{ ns} = 322.5\text{ ns}$$
3. คำนวณ Steady-State Throughput:
   * เมื่อท่อไปป์ไลน์เต็มแล้ว (Pipelined Steady State) ข้อมูลผลลัพธ์ $y[n]$ ใหม่จะหลุดออกจากปลายท่อ **"ในทุกๆ รอบสัญญาณนาฬิกา (1 Sample per Cycle)"**
   $$\text{Throughput} = f_{clk} = 400\text{ Mega-Samples/sec (MSPS)}$$
4. **ข้อสรุปเชิงวิศวกรรม:**
   * แม้ว่าจะมีความล่าช้าเริ่มต้น $129$ ไซเคิล ($322.5\text{ ns}$) ในช่วงเริ่มเดินเครื่อง แต่หลังจากนั้นระบบจะประมวลผลได้เต็มสปีด $400\text{ ล้านตัวอย่างต่อวินาที}$ อย่างต่อเนื่องโดยไม่มีอาการกระตุก

### ข้อที่ 2: การประเมินการประหยัดพลังงานและพื้นที่ซิลิคอนจาก Symmetric Pre-Adder
ระบบประมวลผลสถานีฐาน 5G ใช้ตัวกรอง Digital Down Converter (DDC) ชนิด Symmetric Linear-Phase FIR ขนาด **$N = 96\text{ Taps}$**:
* หากสร้างด้วยโครงสร้างมาตรฐานที่ไม่มี Pre-Adder: ต้องใช้ตัวคูณ 96 ชุด (DSP48E2 จำนวน 96 บล็อก)
* หากเปิดใช้งาน **Symmetric Pre-Adder**: ข้อมูลคู่สมมาตร $x[k] + x[96-1-k]$ จะถูกบวกกันก่อนเข้าตัวคูณ

กำหนดให้:
* บล็อก DSP48E2 แต่ละบล็อกกินพลังงานพลวัตเฉลี่ยที่ 400 MHz เท่ากับ $P_{dsp} = 18.5\text{ mW}$
* การใช้ Pre-Adder เพิ่มพลังงานในตัว DSP48 แต่ละตัวเพียงเล็กน้อย $+1.2\text{ mW}$

จงคำนวณหาจำนวน **บล็อก DSP48E2 ที่ประหยัดได้** และคำนวณหา **กำลังไฟฟ้าที่ประหยัดได้รวม (Total Power Saved)**:

a) ประหยัดได้ 32 บล็อก; กำลังไฟฟ้าประหยัดได้ $450\text{ mW}$  
b) ประหยัดได้ 48 บล็อก; กำลังไฟฟ้าประหยัดได้ $830.4\text{ mW}$  
c) ประหยัดได้ 48 บล็อก; กำลังไฟฟ้าประหยัดได้ $1,776.0\text{ mW}$  
d) ประหยัดได้ 24 บล็อก; กำลังไฟฟ้าประหยัดได้ $320.0\text{ mW}$

**คำตอบที่ถูกต้องคือ: b) ประหยัดได้ 48 บล็อก; กำลังไฟฟ้าประหยัดได้ $830.4\text{ mW}$**

**ขั้นตอนการคำนวณทางคณิตศาสตร์:**
1. คำนวณจำนวนบล็อก DSP48 ที่ต้องใช้ในแต่ละกรณี:
   * กรณีเดิม (ไม่มี Pre-Adder): ใช้ $N = 96\text{ บล็อก}$
   * กรณีใหม่ (ใช้ Pre-Adder): ใช้ $\frac{N}{2} = \frac{96}{2} = 48\text{ บล็อก}$
   * จำนวนบล็อกที่ประหยัดได้:
     $$\Delta N_{DSP} = 96 - 48 = 48\text{ บล็อก (ลดลง 50%!)}$$
2. คำนวณกำลังไฟฟ้ารวมในกรณีเดิม:
   $$P_{old} = 96 \times 18.5\text{ mW} = 1,776.0\text{ mW}$$
3. คำนวณกำลังไฟฟ้ารวมในกรณีใหม่:
   $$P_{new} = 48 \times (18.5 + 1.2)\text{ mW} = 48 \times 19.7\text{ mW} = 945.6\text{ mW}$$
4. คำนวณกำลังไฟฟ้าที่ประหยัดได้สุทธิ:
   $$P_{saved} = P_{old} - P_{new} = 1,776.0\text{ mW} - 945.6\text{ mW} = 830.4\text{ mW} \approx 0.83\text{ W}$$
5. **ข้อสรุปเชิงวิศวกรรม:**
   * การเขียนโค้ด VHDL ให้ดึง Pre-Adder มาใช้งาน ช่วยปลดปล่อยบล็อก DSP48 คืนให้ระบบถึง 48 บล็อก และลดความร้อนของชิปลงได้ถึงเกือบ **$1\text{ วัตต์}$** ซึ่งมีคุณค่ามหาศาลในอุปกรณ์สถานีฐานกลางแจ้ง

### ข้อที่ 3: ผลกระทบของการตัดบิต (Truncation) เทียบกับการปัดเศษ Round-to-Nearest ต่อค่า DC Bias
พิจารณาวงจรกรองดิจิทัลที่ทำการลดขนาดคำข้อมูลจาก 32 บิต ลงเหลือ 16 บิต โดยการกำจัดบิตทศนิยมล่างสุดจำนวน $n = 16\text{ บิต}$:

ตามทฤษฎีการวิเคราะห์สัญญาณรบกวนจากการคำนวณ (Arithmetic Quantization Error):
* หากใช้วิธี **Truncation (การตัดทิ้ง)**: ค่าความผิดพลาดของการควอนไทซ์ $e = x_{quantized} - x_{real}$ จะมีค่าเฉลี่ยเป็นเท่าใด?
* หากใช้วิธี **Round-to-Nearest (四捨五入)**: ค่าเฉลี่ยของความผิดพลาดจะเป็นเท่าใด?

a) Truncation: ค่าเฉลี่ย $= 0$; Rounding: ค่าเฉลี่ย $= +0.5\text{ LSB}$  
b) Truncation: เกิดค่าเบี่ยงเบนคงที่ (DC Bias) เท่ากับ **$-0.5\text{ LSB}$**; Rounding: ค่าเฉลี่ยของความผิดพลาดเป็นศูนย์ (**Zero DC Bias**)  
c) ทั้งสองวิธีให้ผลลัพธ์เหมือนกันทุกประการ  
d) Truncation มีสัญญาณรบกวนต่ำกว่า Rounding  

---

#### เฉลยและบทวิเคราะห์เชิงลึกข้อที่ 3
**คำตอบที่ถูกต้องคือ: b) Truncation: เกิดค่าเบี่ยงเบนคงที่ (DC Bias) เท่ากับ $-0.5\text{ LSB}$; Rounding: ค่าเฉลี่ยของความผิดพลาดเป็นศูนย์ (Zero DC Bias)**

**บทวิเคราะห์เชิงลึกระดับ DSP Architect:**
* **พฤติกรรมของการ Truncation (ตัดบิตทิ้ง):**
  * สำหรับตัวเลขจำนวนบวก การตัดบิตล่างทิ้งจะทำให้ค่าลดลงเสมอ ($e \in [-(1 - 2^{-n}), 0]$)
  * ค่าเฉลี่ยทางสถิติ (Expected Value):
    $$E[e_{trunc}] = -\frac{1}{2} \cdot \text{LSB} = -0.5\text{ LSB}$$
  * การมี DC Bias ติดลบค้างอยู่ในสัญญาณ จะถูกขยายตัวในระบบที่มีวงจรป้อนกลับ (เช่น IIR Filter หรือ Control Loop Integrator) ทำให้เกิดการดริฟต์ของระดับแรงดันไฟตรง และลดทอน Dynamic Range ของระบบ
* **พฤติกรรมของการ Round-to-Nearest:**
  * การบวก $0.5 \times LSB$ เข้าไปก่อนตัดบิต จะกระจายความผิดพลาดให้อยู่ในช่วงสมมาตร $e \in [-0.5\text{ LSB}, +0.5\text{ LSB}]$
  * ค่าเฉลี่ยทางสถิติ:
    $$E[e_{round}] = 0.0\text{ LSB}$$
  * สัญญาณรบกวนจากการคำนวณจะกลายเป็นสัญญาณรบกวนสีขาวแบบสุ่ม (White Noise) โดยปราศจาก DC Offset ตกค้าง ช่วยรักษาความบริสุทธิ์ของสัญญาณในระดับมืออาชีพ
